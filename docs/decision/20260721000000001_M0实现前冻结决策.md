# M0 实现前冻结决策

## 状态

已接受，生效日期：2026-07-21。

## 背景

开发前审计发现 P0/P1 骨架早于当前权威文档，数据库、会话终态、API canonical、wire kind/channel、密码学输出长度和客户端能力 schema 存在缺口。用户确认修订后进入 V1 Core 实施。

## 决策

1. 当前项目初始化本地 Git；不自动 commit、push、reset、rebase。
2. `0001_initial_schema.sql` 从未进入共享环境，T002E 直接重写为正式 V1 Core schema。
3. 被控端拒绝使用独立终态 `rejected`，不得复用 `closed`。
4. 平台枚举固定为 `windows | ubuntu | ios`，系统版本写入 `os_version`。
5. JSON API body canonical 固定使用 RFC 8785 JCS；path/query 按 RFC 3986 规则规范化后参与设备签名和 step-up binding。
6. 会话密钥固定使用 X25519、Ed25519、HKDF-SHA256、HMAC-SHA256 和 ChaCha20-Poly1305；nonce 为 `prefix_u32 || channel_id_u16 || sequence_u48`。
7. 协议版本 1 的 40-byte header、kind、channel ID 和 QUIC/TLS fallback 映射按协议设计固定表实现。
8. 临时验证码业务有效期固定 5 分钟；OPAQUE 未完成 registration 中间记录最多保留 24 小时，但不能延长验证码有效期。
9. iOS 最低版本保持 iOS 16，且只提供主控能力。

## 影响

- M0 的 T001-T002O 标记为完成，T002E 开始实施。
- 旧 P1 migration、38-byte header、5 项权限和未鉴权 Signal 行为必须被替换。
- Windows、Ubuntu X11 和 iOS 真机缺少验证环境时保留发布阻断，不能用 mock 或静态原型替代真实验收。

## 回滚

协议版本 1 发布前可通过新的 ADR 修改并同步协议、数据库、客户端、服务端、测试和任务清单。协议版本 1 发布后不得原地修改 wire contract，必须升级协议版本并提供兼容策略。
