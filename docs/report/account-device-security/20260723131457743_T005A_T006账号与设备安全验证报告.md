# T005A/T006 账号与设备安全验证报告

## 结论

`T005A` 与 `T006` 已通过内存仓储回归、隔离 PostgreSQL/Redis 真实集成测试和工作区质量门禁，可以标记为 `done`。

本报告只关闭账号安全与设备管理任务，不代表 Signal、远控链路、桌面/iOS 壳层或平台真机门禁已经完成。

## 实现范围

- 两段式登录、TOTP MFA、恢复码、风险 challenge、受信任主控设备、step-up token、改密和 refresh rotation 均以 PostgreSQL 为事实源，Redis 仅作为尽力缓存。
- 登录、refresh、改密、MFA 变更、设备解绑/撤销/密钥轮换的状态变化、逐对象审计和会话/trust 撤销在事务内闭合，冲突或审计失败时整体回滚。
- enrollment grant 同时绑定账号、设备、登录 challenge/session、公钥 fingerprint、协议版本和有效期；注册锁定 grant 后重新验签，并持久化首次不可变注册结果。
- 注册幂等重放从 `device_registered` 审计中的 `device_registration_result_v1` 快照恢复，不依赖设备当前名称、状态或密钥版本；快照不保存 secret、token、签名、nonce 或 canonical body。
- 设备列表、改名、禁用/恢复、解绑、公钥轮换和撤销执行账号归属校验；高风险密钥替换要求 step-up，新密钥 proof 通过后旧私钥失效。
- Ubuntu 桌面注册首版仅接受 `x86_64`；`controlled` 能力仍由本机授权决定，不在服务端注册时强制设为 true。

## 验证证据

1. `make fmt-check`：通过。
2. `make lint`：通过。
3. `make check`：通过。
4. `make test`：通过；Relay QUIC/TLS 测试因需要绑定本机临时端口，在允许本机端口绑定的隔离环境执行。
5. API 常规测试：`95 passed; 0 failed; 25 ignored`。
6. 使用已迁移的隔离 PostgreSQL 和 Redis 显式执行 ignored 真库测试：`25 passed; 0 failed`。
7. PostgreSQL 密钥轮换专项回归：新密钥 proof 成功，轮换后旧私钥请求被拒绝。
8. 注册 grant 负例覆盖 secret 错误、跨账号、跨设备、跨 fingerprint、跨 challenge/session、过期、已消费、并发竞争和注册字段变化。
9. MFA/账号安全矩阵覆盖 TOTP 30 天 trust、恢复码 24 小时 trust、重放拒绝、改密撤销、refresh 与安全撤销竞态、审计冲突回滚和 Redis 缺失后的 PostgreSQL 恢复。
10. 设备管理矩阵覆盖账号隔离、跨账号 PATCH、缺少设备签名、解绑、密钥轮换、旧 trust/session 撤销，以及双方 `session_close_ack` 使用同一事件 ID。

## 回滚与边界

- 回滚时可禁用新登录完成、密码修改、MFA、设备注册和设备 PATCH 入口，既有设备仅保留只读；不得恢复“仅凭 access token 注册新设备”的旧路径。
- 本任务未执行 Windows、Ubuntu Wayland/X11 或 iOS 真机远控验收；这些门禁属于后续客户端、媒体链路和平台矩阵任务，仍保持发布阻断。
- 本任务未执行生产迁移、生产部署、签名发布、Git commit 或 push。
