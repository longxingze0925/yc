# AI 开发实施计划

文档状态：历史计划，仅保留背景。当前 AI 开发必须以 `docs/plan/20260719170217641_AI开发任务清单.md`、`docs/plan/20260719170217641_里程碑计划.md` 和 `docs/spec/**` 的冻结文档为准。

## 1. 执行原则

本项目后续由 AI Agent 逐步开发。开发顺序必须围绕最小可运行闭环，不先做外观包装、不先做企业后台、不先追求极限性能。

## 当前进度

已完成：

- P0 Rust workspace 工程骨架。
- P0 核心协议、核心状态、传输、加密、采集、渲染抽象 crate。
- P0 API、信令、Relay 空服务。
- P1 `signal-server` HTTP + WebSocket 入口。
- P1 设备注册、在线状态、验证码校验核心模型。
- P1 PostgreSQL 初始迁移和数据记录模型。

下一步：

- `api-server` 接账号、设备和会话 HTTP API。
- 引入 PostgreSQL/Redis 本地编排。
- 将 `signal-server` 内存状态替换为 PostgreSQL + Redis。
- 实现会话邀请定向推送。

最小闭环：

```text
设备注册 -> 主控发起连接 -> 信令协商 -> 建链 -> 画面传输 -> 输入回传 -> 断开清理 -> 审计记录
```

## 2. 阶段路线

### P0 工程骨架

目标：

- 建立 monorepo 或多仓库结构
- 固化 Rust core、server、desktop、ios、admin 的模块边界
- 定义协议消息和错误码
- 建立基础 CI 和本地开发命令

建议目录：

```text
crates/
  remote-core/
  remote-protocol/
  remote-transport/
  remote-crypto/
  remote-capture/
  remote-render/
apps/
  desktop/
  ios/
  admin-web/
services/
  api-server/
  signal-server/
  relay-server/
infra/
  docker-compose/
  migrations/
docs/
```

验收：

- 所有模块可独立构建
- 本地能启动 API、信令、Relay 空服务
- 协议 crate 有单元测试

### P1 信令和设备系统

目标：

- 账号登录
- 设备注册
- 设备在线状态
- WebSocket Secure 信令
- 设备 ID + 验证码连接

核心任务：

- 设计 `device_id`
- 设计设备长期密钥对
- 设计在线状态模型
- 设计会话邀请和确认流程
- 设计验证码有效期和重试限制

验收：

- 被控端上线后主控端能看到在线状态
- 主控端能发起连接请求
- 被控端能确认或拒绝
- 会话状态可追踪

### P2 QUIC 传输和 Relay

目标：

- 建立 P2P over QUIC
- 建立 QUIC Relay
- 建立 TLS 443 Relay
- 实现连接竞速和断线重连

核心任务：

- 地址候选交换
- LAN 探测
- UDP P2P 尝试
- Relay 分配
- 链路质量评估
- 会话密钥协商

验收：

- 同局域网优先直连
- P2P 失败自动 Relay
- Relay 中断后能重连
- 控制通道和视频通道优先级不同

### P3 Windows 被控和主控

目标：

- Windows 屏幕采集
- Windows 输入注入
- Windows 主控显示
- Slint 桌面 UI

核心任务：

- Windows Graphics Capture
- DXGI fallback
- SendInput
- D3D11 渲染
- 托盘和连接状态提示
- Windows Service 无人值守

验收：

- Windows 控 Windows 可用
- 输入可达
- 断开后输入和采集资源释放
- 被控端有明显连接状态

### P4 Ubuntu 26.04 LTS 被控和主控

目标：

- Ubuntu Wayland/PipeWire 采集
- X11 fallback
- Ubuntu 输入控制
- Ubuntu 主控显示

核心任务：

- PipeWire + xdg-desktop-portal ScreenCast
- xdg-desktop-portal RemoteDesktop
- XDamage + XShm
- XTest + uinput
- OpenGL/Vulkan 渲染
- systemd 服务

验收：

- Ubuntu 控 Ubuntu 可用
- Ubuntu 被 Windows 主控可用
- Ubuntu 被 iOS 主控可用
- Wayland 权限边界清晰提示

### P5 iOS 主控端

目标：

- iOS 登录和设备列表
- iOS 远控画面显示
- iOS 输入映射
- iOS 文件和剪贴板基础能力

核心任务：

- SwiftUI/UIKit UI
- Rust Core FFI
- VideoToolbox 解码
- Metal 渲染
- 触控映射
- 虚拟键盘
- 外接键鼠支持

验收：

- iOS 控 Windows 可用
- iOS 控 Ubuntu 可用
- 横竖屏切换正常
- 触控、键盘、滚轮映射可用

### P6 可商用打磨

目标：

- 多显示器
- 文本剪贴板
- 基础文件传输
- 无人值守访问
- 会话日志
- 弱网自适应

验收：

- 常见家庭宽带、公司网络、热点网络可连接
- Relay 流量可统计
- 会话异常可追踪
- 用户能看懂连接状态和失败原因

### P7 企业化预留

目标：

- 管理后台
- 组织/成员/角色
- 策略下发
- 审计
- 私有化部署

第一版只预留数据模型和接口边界，不阻塞 MVP。

## 3. 推荐 Agent 分工

```text
Agent-Core
  Rust core、协议、加密、状态机、传输抽象

Agent-Server
  API、信令、Relay、PostgreSQL、Redis

Agent-Desktop-Windows
  Windows 采集、输入、服务、渲染

Agent-Desktop-Ubuntu
  Ubuntu 采集、输入、服务、渲染

Agent-iOS
  iOS UI、Metal、VideoToolbox、触控映射、Rust FFI

Agent-QA
  连接矩阵、弱网、回归、安装包验证
```

## 4. 第一批开发任务

建议后续 AI 从这些任务开始：

1. 搭建仓库骨架和 Rust workspace。
2. 定义协议消息：设备注册、会话邀请、连接状态、输入事件、视频帧元信息。
3. 实现 `api-server` 空服务和健康检查。
4. 实现 `signal-server` WebSocket 长连接。
5. 实现桌面端最小登录/设备注册 CLI。
6. 实现本机回环 QUIC 通道验证。
7. 实现 Windows 屏幕采集 POC。
8. 实现 Ubuntu PipeWire 采集 POC。
9. 实现 iOS H.264 解码和 Metal 显示 POC。

## 5. 阶段验收矩阵

```text
Windows 被控 -> Windows 主控
Windows 被控 -> Ubuntu 主控
Windows 被控 -> iOS 主控
Ubuntu 被控 -> Windows 主控
Ubuntu 被控 -> Ubuntu 主控
Ubuntu 被控 -> iOS 主控
```

每条链路至少覆盖：

- LAN
- 公网 P2P
- Relay
- TLS 443 fallback
- 断线重连
- 被控端主动断开
