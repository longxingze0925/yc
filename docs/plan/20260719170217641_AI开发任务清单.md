- 测试矩阵

- 发布验收

## 3. 任务状态定义

每个任务必须有：

- 目标。
- 输入文档。
- 负责文件。
- 验收标准。
- 验证命令。
- 风险。
- 回滚方式。

状态：

- `todo`
- `in_progress`
- `blocked`
- `done`


- 必须有迁移说明。

- 必须有画面非空证据。

## 5A. T002P/T005A 增补门禁

以下契约属于 T002P/T005A 的联合门禁。T002P 在最终 `0001` 已通过空库迁移和 Schema 验证后可以独立标记 `done`，不因后续运行时门禁未完成而回退；其余账号安全实现或真实 PostgreSQL 门禁未满足时，T005A 必须保持 `todo`，不得进入 T006：

- `account_risk_challenges.login_account_updated_at_epoch_millis` 必须保存第一段登录读取的账号安全版本，并纳入 `login_challenge_binding_hash`；创建和 finish 均锁定账号并严格比较快照，覆盖同毫秒、时钟回拨及改密/MFA 并发。
- Memory 与 PostgreSQL 必须共用 login finish authority 校验，覆盖 grant/trust 的账号、设备、challenge、session、fingerprint、TTL、因子决策、未消费形状和审计集合唯一性。
- 每条实际撤销的 session/trust 必须有对应对象审计；密码/MFA、challenge 消费、撤销、对象审计和顶层审计，以及 logout 的 session 撤销和审计，必须同事务全成全败。
- 必须补并通过 Memory 回归测试和隔离、已迁移 PostgreSQL 的真实账号安全测试；未成功执行 `API_TEST_DATABASE_URL=... cargo test -p api-server -- --ignored` 时，不能解除 M2/T005A 阻断。
