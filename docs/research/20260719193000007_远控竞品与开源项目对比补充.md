# 远控竞品与开源项目对比补充

## 1. 目的

本文用于记录文档冻结前的对标依据。结论只作为产品和架构补强输入，后续实现仍以 `docs/spec/**` 和 `docs/plan/**` 为准。

## 2. 参考对象

开源或可自建项目：

- RustDesk / rustdesk-server：自建信令和中继、P2P 优先、Relay 兜底。
- MeshCentral：基于 agent 的设备管理和浏览器远程管理。
- Apache Guacamole：网关式远程桌面架构，适合理解“服务端代理”和端到端明文边界。
- Moonlight / Sunshine：低延迟串流、硬件编解码和质量调参。

商业软件：

- TeamViewer：条件访问、企业策略、会话录制和安全治理。
- AnyDesk：权限 profile、无人值守、远程重启、反诈骗提示。
- NoMachine：屏幕 blanking、本地键鼠锁定和企业部署。
- Parsec：低延迟媒体、硬件编解码和 4:4:4/高性能体验边界。
- ToDesk、向日葵、UU 远程：国内远控产品常见能力，如远程开机、隐私屏、文件传输、低延迟和易用连接。

## 3. 对当前方案的确认

当前技术路线仍成立：

- Rust Core。
- Slint 桌面 UI。
- SwiftUI/UIKit iOS。
- QUIC 主传输。
- P2P 优先，Relay 兜底，TLS 443 极端兜底。
- 应用层端到端加密。
- API/Signal/Relay 不得解密远控业务明文。

该路线比单纯网关代理更适合低延迟和私有化成本控制；比纯 WebRTC 更利于统一 Rust 协议、Relay token、设备签名和文件传输权限模型。

## 4. 需要补强的能力

对标后新增 6 个文档冻结项：

1. 反诈与滥用防护。
2. 远程重启与会话恢复。
3. 键盘、IME 与快捷键输入。
4. 媒体质量控制与能力协商。
5. 会话录制与合规审计边界。
6. 企业区域路由与数据驻留。

## 5. 决策边界

进入 V1 Core：

- 反诈与滥用防护基础能力。
- 远程重启与重启后新会话恢复。
- 键盘、IME 与快捷键输入。
- 媒体质量控制与能力协商。

进入 V1 Commercial/M8 或 V2：

- 生产会话录制。
- 企业区域路由和数据驻留。
- 企业反滥用后台和处置工单。

明确不做：

- 服务端集中解密录制。
- 绕过系统权限的输入、隐私屏、重启或安全桌面控制。
- 远程开机，包括 WOL、智能插座唤醒、带外管理唤醒或任何绕过被控端本地授权的物理唤醒能力；是否进入 `V1 Commercial/M8` 必须另行 ADR 冻结。
- V1 承诺 H.265、AV1、4K/144fps 或游戏级体验。
