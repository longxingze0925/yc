# 远程控制软件产品技术规格

文档状态：历史方案，仅保留背景。当前产品、架构、协议、数据库和开发任务必须以 README 文档入口中的 `20260719170217641` 与 `20260719171718533` 系列冻结文档为准。

## 1. 目标

开发一套面向个人、团队和企业的商业级远程控制软件。第一版聚焦 Windows 和 Ubuntu 被控，iOS 16 及以上、Windows、Ubuntu 主控，优先实现稳定连接、低延迟控制、安全授权和可审计。

核心定位：

```text
高性能远控 + 可私有化 + iOS 主控体验好 + Ubuntu 认真适配
```

## 2. 平台范围

被控端：

- Windows 10/11
- Ubuntu Desktop 26.04 LTS x86_64

主控端：

- iOS 16 及以上
- Windows 10/11
- Ubuntu Desktop 26.04 LTS x86_64

暂不做：

- iOS 被控端完整远控
- 浏览器被控端
- Android 端
- macOS 端
- 绕过系统权限的静默控制

## 3. 核心连接模型

最终模型：

```text
P2P 优先 + QUIC 主传输 + Relay 兜底 + TLS 443 极端兜底
```

P2P 是连接路径，QUIC 是传输协议。能直连时使用 P2P over QUIC，不能直连时使用 Relay over QUIC，UDP 被封时使用 TLS 443 Relay。

连接优先级：

```text
1. LAN Direct
2. UDP P2P
3. QUIC Relay
4. TLS 443 Relay
```

## 4. 会话流程

```text
1. 被控端启动并连接信令服务器
2. 被控端注册设备身份并上报在线状态
3. 主控端登录并获取设备列表
4. 主控端发起连接
5. 服务端校验账号、设备和权限
6. 被控端弹窗确认，或校验无人值守凭据
7. 双方交换候选地址和会话参数
8. 同时尝试 LAN、UDP P2P 和 Relay
9. 选择质量最好的链路
10. 建立端到端会话密钥
11. 被控端采集、编码并发送画面
12. 主控端解码、渲染并回传输入事件
13. 会话结束后清理资源并写入审计日志
```

## 10. 传输通道策略

视频：

- 优先低延迟
- 可丢帧
- 不允许旧帧堆积造成控制卡顿

输入控制：

- 最高优先级
- 可靠投递
- 需要顺序保证

剪贴板：

- 可靠投递
- 独立权限

文件传输：

- 可靠投递
- 支持限速
- 不能抢占远控交互带宽

心跳和统计：

- 周期上报 RTT、丢包、抖动、码率、帧率、CPU、内存

## 12. 安全要求

必须实现：

- 设备长期密钥对
- 账号身份和设备身份分离
- 端到端会话密钥
- 临时验证码短有效期
- 无人值守密码本地加密保存
- 被控端明显连接状态提示
- 一键断开
- 黑名单
- 文件传输独立授权
- 剪贴板独立授权
- 会话审计日志
- 异常登录风控

禁止实现：

- 隐藏运行远控
- 绕过用户授权
- 绕过系统安全提示
- 静默采集屏幕
- 静默启用摄像头或麦克风
- 无审计无人值守

## 13. 第一版验收

第一版完成时必须证明：

- Windows 被控到 Windows 主控可远控
- Windows 被控到 iOS 主控可远控
- Ubuntu 被控到 Windows 主控可远控
- Ubuntu 被控到 iOS 主控可远控
- P2P 成功时不走 Relay
- P2P 失败时可自动走 Relay
- UDP 被封时可走 TLS 443 Relay
- 被控端可确认和断开
- 无人值守可配置、可禁用、可审计
- 输入延迟和画面帧率有可观测指标
