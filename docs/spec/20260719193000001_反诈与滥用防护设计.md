# 反诈与滥用防护设计

## 1. 目标

远程控制软件容易被用于冒充客服、诱导转账、批量撞库、验证码枚举和 Relay 滥用。反诈设计的目标不是代替用户判断，而是在不破坏合法远程协助的前提下，降低高风险会话成功率，并让被控端始终看得见、停得下、追得回。

目标：

- 临时协助和陌生账号连接必须有明确风险提示。
- 验证码、会话创建、无人值守 proof 和 Relay 使用必须限流。
- 支持被控端一键举报、拉黑和断开。
- 支持账号、设备、IP/ASN、Relay 使用维度的滥用处置。
- 所有拦截、放行、举报和处置必须可审计。
- 风控不得绕过 MFA、设备签名、被控端确认、应用层端到端加密和权限模型。

## 2. 范围

`V1 Core` 必须实现：

- 陌生主控端临时协助风险提示。
- 被控端连接前确认和连接中明显状态。
- 连接前敏感操作提示，例如不要透露验证码、密码、短信验证码和付款信息。
- 验证码枚举、会话创建、登录、无人值守 proof 和 Relay token 的基础限流。
- 被控端一键举报、断开和拉黑。
- 账号、设备和会话级滥用审计。
- 处置动作：警告、冷却、强制 MFA、强制被控端确认、禁用无人值守、拒绝新会话、封禁设备或账号。

`V1 Commercial/M8` 增强：

- 企业级反滥用策略后台。
- 组织级举报流转、处置工单和白名单。
- Relay 节点级滥用统计和区域封禁策略。
- 管理员批量封禁、解封和申诉记录。

不做：

- 服务端读取远控画面、剪贴板、文件内容来做风控。
- 静默监听摄像头、麦克风或键盘内容。
- 使用反诈规则绕过用户授权或隐藏远控状态。
- 仅凭 IP、地区或 ASN 判断用户身份。

## 3. 风险信号

账号维度：

- 登录失败过多。
- 新主控设备登录。
- 受信任设备状态异常。
- MFA 频繁失败。
- 短时间发起大量临时协助会话。

设备维度：

- 同一主控设备短时间连接大量陌生被控设备。
- 同一被控设备频繁生成验证码或频繁被陌生账号请求。
- 无人值守 proof 失败过多。
- 被控端多次举报同一账号或设备。

网络维度：

- IP、ASN、地区突变。
- 数据中心代理、匿名代理或异常出口。
- Relay 流量远超同类用户基线。
- TLS 443 Relay 被异常高频使用。

会话维度：

- 临时验证码连续错误。
- 被控端拒绝后主控端重复请求。
- 连接后立即请求文件传输、剪贴板、隐私屏或本地输入保护。
- 重启后恢复请求异常频繁。

规则：

- 风险信号只能作为 `allow | require_mfa | require_prompt | cooldown | deny` 决策输入。
- 风险信号不能替代设备长期签名、验证码 proof、无人值守 proof 或被控端确认。
- 风险模型不得依赖远控业务明文。

## 4. 产品交互

临时协助连接前，被控端必须展示：

- 主控端账号昵称或标识。
- 主控端设备名称和大致地区。
- 连接权限摘要。
- 风险提示。
- 接受、拒绝、举报并拒绝。

连接中，被控端必须展示：

- 当前正在被远控。
- 主控端标识。
- 连接路径是否 Relay。
- 剪贴板、文件传输、隐私屏、本地输入保护状态。
- 一键断开。
- 举报入口。

高风险能力请求时，被控端必须二次提示：

- 文件传输。
- 剪贴板开启。
- 隐私屏。
- 本地输入保护。
- 远程重启。

提示原则：

- 不使用恐吓式文案。
- 不在 UI 中隐藏断开、拒绝或举报入口。
- 不要求被控端透露密码、验证码、短信验证码、支付信息或私钥。

## 5. 决策结果

反滥用评估结果：

- `allow`：允许继续。
- `warn_user`：允许继续，但被控端和主控端显示风险提示。
- `require_mfa`：主控端账号必须完成 step-up。
- `require_prompt`：必须被控端当次确认。
- `cooldown`：短时间内拒绝重复请求。
- `deny_session`：拒绝创建或继续会话。
- `disable_unattended`：禁用目标设备无人值守能力。
- `suspend_device`：暂停设备发起或接受会话。
- `suspend_account`：暂停账号远控能力。
- `relay_quarantine`：禁止使用 Relay 或限制 Relay 带宽。

规则：

- `deny_session` 优先级高于 `allow`。
- `require_prompt` 不能被无人值守 proof 绕过。
- `disable_unattended`、`suspend_device` 和 `suspend_account` 必须写审计，并提供恢复路径。
- 平台自动处置必须保守，误报恢复优先走人工或管理员确认。
- 反滥用结果不得由会话创建逻辑单独解释，必须与条件访问结果合成为统一 `session_access_decision`；合成优先级以 `docs/spec/20260719190000002_访问控制与条件访问设计.md` 为准。
- `relay_quarantine` 命中时必须影响 Relay 分配或带宽策略，并写审计；客户端不能自行忽略。

## 6. API 设计

V1 Core API：

```text
POST /v1/abuse-reports
GET  /v1/devices/{device_id}/abuse-status
POST /v1/sessions/{session_id}/abuse/risk-evaluate
```

M8 管理 API：

```text
GET  /v1/admin/abuse/cases
GET  /v1/admin/abuse/cases/{abuse_case_id}
PATCH /v1/admin/abuse/cases/{abuse_case_id}
POST /v1/admin/abuse/enforcement-actions
POST /v1/admin/abuse/enforcement-actions/{enforcement_action_id}/revoke
```

规则：

- `POST /v1/abuse-reports` 必须接受被控端设备签名，不能只信任账号 token。
- 举报内容只能包含分类、原因、会话 ID、对端账号/设备 ID、截图是否由用户主动附加、客户端日志摘要和时间。
- 默认不上传屏幕截图；如果允许用户主动附加证据，必须单独确认，并按合规策略保存。
- `abuse/risk-evaluate` 只能返回策略决策和元数据，不返回敏感规则细节。

## 7. 数据模型

需要纳入 Schema Freeze 的逻辑表：

- `abuse_reports`
- `abuse_cases`
- `abuse_enforcement_actions`
- `abuse_risk_events`

`abuse_reports` 关键字段：

- `abuse_report_id`
- `reporter_account_id`
- `reporter_device_id`
- `reported_account_id`
- `reported_device_id`
- `session_id`
- `category`
- `reason`
- `status`
- `created_at_epoch_millis`

`abuse_cases` 关键字段：

- `abuse_case_id`
- `primary_report_id`
- `subject_account_id`
- `subject_device_id`
- `risk_level`
- `status`
- `assigned_to_account_id`
- `created_at_epoch_millis`
- `updated_at_epoch_millis`
- `closed_at_epoch_millis`

`abuse_enforcement_actions` 关键字段：

- `enforcement_action_id`
- `abuse_case_id`
- `subject_type`
- `subject_id`
- `action`
- `reason`
- `starts_at_epoch_millis`
- `expires_at_epoch_millis`
- `created_by_actor_type`
- `created_by_account_id`
- `revoked_at_epoch_millis`

`abuse_risk_events` 关键字段：

- `risk_event_id`
- `account_id`
- `device_id`
- `session_id`
- `event_type`
- `risk_level`
- `signals`
- `decision`
- `created_at_epoch_millis`

规则：

- `signals` 可以用 JSONB 起步，但必须做 schema 校验和敏感字段裁剪。
- 不保存远控画面、剪贴板内容、文件内容、按键内容、验证码明文、MFA code 或完整 token。
- 反滥用处置不得使用会清空审计归因的级联删除。

## 8. 审计

必须新增或支持审计动作：

- `abuse_report_created`
- `abuse_case_opened`
- `abuse_case_updated`
- `abuse_case_closed`
- `abuse_risk_evaluated`
- `abuse_warning_shown`
- `abuse_enforcement_applied`
- `abuse_enforcement_revoked`
- `session_rate_limited`
- `verification_code_rate_limited`
- `unattended_rate_limited`
- `relay_rate_limited`

审计 metadata 允许记录：

- `risk_level`
- `decision`
- `matched_rule_ids`
- `cooldown_seconds`
- `enforcement_action_id`
- `abuse_case_id`

禁止记录：

- 远控画面内容。
- 剪贴板内容。
- 文件内容。
- 按键内容。
- 远程重启 reason 自由文本。
- 验证码、MFA code、无人值守密码或 token 明文。

## 9. 测试要求

必须验证：

- 临时协助展示陌生主控端风险提示。
- 被控端可以举报并拒绝会话。
- 被控端举报后可自动拉黑同一主控设备。
- 短时间验证码错误过多触发冷却。
- 短时间会话创建过多触发限流。
- 无人值守 proof 失败过多触发冷却或禁用。
- Relay token 高频失败触发 Relay 限制。
- 被封禁账号和设备不能创建新会话。
- 强制 MFA 和强制被控端确认不能被无人值守 proof 绕过。
- 风控日志和审计不包含业务明文。
- 误报恢复后新会话按正常权限模型重新评估。
