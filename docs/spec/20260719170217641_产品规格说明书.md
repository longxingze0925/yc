# 产品规格说明书

## 1. 产品定位

本产品是一套商业级远程控制软件，面向个人远程办公、技术支持、小团队设备维护和企业私有化管理场景。

核心定位：

```text
高性能远控 + 可私有化 + iOS 主控体验好 + Ubuntu 认真适配
```

第一版优先实现稳定、安全、可审计的远程桌面闭环，不追求一次覆盖所有系统和所有外设能力。

版本边界：

- `V1 Core`：对应 M1-M7，交付个人和小团队可用的远控闭环，包括账号、设备、临时协助、无人值守、P2P/Relay、远程桌面、键盘/IME、媒体质量控制、剪贴板、基础文件传输、远程重启、反诈与审计。
- `V1 Commercial`：对应 M8，交付企业管理后台、组织/成员/角色、策略下发、区域路由、数据驻留和私有化部署体验；生产会话录制默认 `disabled`，只有 `T027B0` 二次冻结决策选择 `implement` 后才纳入 M8 发布门禁。
- M1-M7 可以预留企业数据模型和 API 边界，但管理后台和完整企业策略不作为 `V1 Core` 发布门禁。
- `V2` 不作为当前里程碑验收；高级数据驻留和更多平台能力只保留方向，必须另行冻结规格后开发。生产会话录制仅按会话录制边界文档和 `T027B0` 决策进入 M8/V2，不进入 V1 Core。

## 2. 平台范围

本产品采用**统一客户端模型**：Windows 10/11 与 Ubuntu Desktop 26.04 LTS 的桌面客户端是同一个软件，登录账号后自动注册为账号内的一台设备，默认同时具备主控能力和被控能力。iOS 16 及以上是同一账号下的移动客户端，仅提供主控能力。

桌面客户端按平台能力标记：

- `controller`：可以发起连接、控制其他设备。
- `controlled`：允许其他设备远程连接本机。
- `controller + controlled`：Windows/Ubuntu 默认同时具备。

平台能力矩阵：

| 平台 | controller | controlled | 文件传输 | 无人值守 |
| --- | --- | --- | --- | --- |
| Windows 10/11 | 是 | 是 | 是 | 是 |
| Ubuntu Desktop 26.04 LTS x86_64 | 是 | 是 | 是 | 是 |
| iOS 16 及以上 | 是 | 否 | 是 | 否 |

iOS 主控端最低支持版本在 M0 冻结为 iOS 16。后续如因 Apple SDK、依赖库或安全策略需要提高最低版本，必须先补 ADR 并获得确认，不能由实现任务临时决定。

登录与设备绑定统一语义：

- 桌面客户端首次启动：登录账号 → 自动注册当前桌面设备到账号"我的设备" → 默认具备主控能力。
- 桌面客户端被控能力：默认受本机用户授权、屏幕采集权限和系统输入控制权限约束。被控能力的开启与关闭必须走本地开关，不得隐藏。
- iOS 客户端登录后：注册为账号设备并固定标记 `controller only`，不提供被控入口；只有完成设备签名和 TOTP/recovery 验证时才建立受信任主控设备记录。
- 同一账号内的桌面设备列表展示设备能力标签：`controller+controlled` / `controller only`，避免用户对设备能力产生误解。

账号登录与设备注册契约：

- 桌面和 iOS 客户端都必须在登录前加载或生成设备长期 Ed25519 密钥；密码正确后只创建绑定设备身份、双 nonce、IP、User-Agent 和协议版本的登录 challenge，第一段不得签发 token。
- 客户端必须通过 `POST /v1/auth/login/finish` 提交设备私钥证明和所需 TOTP/recovery 因子，全部验证成功后才签发账号 token。
- 未注册设备还必须取得一次性、最长 5 分钟的 `device_enrollment_grant`，再以账号 token、grant 和拟注册私钥签名完成设备注册；任意 access token 不具备新增设备权限。
- 无 MFA 账号仍可在登录后自动加入"我的设备"，但该路径不得创建 `trusted_controller_devices`；普通登录和 refresh 不得延长受信任设备有效期。

暂不支持：

- iOS 被控端完整远控
- Android
- macOS
- 浏览器被控端
- 浏览器主控端
- 绕过系统权限的静默控制
- 远程开机、WOL、智能插座唤醒或带外管理唤醒

## 3. 核心用户

个人用户：

- 从 iPhone 远程控制家里或办公室电脑。
- 从 Windows/Ubuntu 控制另一台 Windows/Ubuntu。

技术支持人员：

- 通过设备 ID 和验证码临时接入用户电脑。
- 临时接入的目标是账号内的桌面设备（具备被控能力）。被控端必须可见、可确认、可断开。

团队管理员：

- `V1 Core` 可以查看本账号设备、会话日志和基础权限。
- `V1 Commercial` 管理成员、设备、权限、策略和审计日志。
- `V1 Core` 可以使用官方托管基础服务完成个人/小团队远控闭环，但不包含商业 SaaS 运营后台、计费、企业组织策略和私有化交付。
- 完整商业 SaaS 运营和私有化部署属于 `V1 Commercial` 验收范围。

## 4. 第一版功能

必须实现：

- 账号登录
- 账号 MFA 和高风险操作 step-up 验证
- 反诈与滥用防护基础能力
- 设备绑定
- 设备在线状态
- 设备 ID + 验证码连接
- 被控端确认
- 无人值守访问
- 远程桌面画面
- 鼠标、键盘、滚轮控制
- 键盘、IME 和常用组合键处理
- iOS 触控映射
- 多显示器基础支持
- 媒体能力协商、动态码率、降帧、降分辨率和关键帧请求
- 文本剪贴板同步
- 基础文件传输
- 隐私屏和本地输入保护的独立权限、显式授权和断开恢复
- 远程重启被控设备并以新会话恢复
- P2P 优先连接
- Relay 兜底连接
- TLS 443 极端兜底
- 会话日志
- 被控端一键断开
- 客户端安装包签名、更新 manifest 签名和 SBOM

基础文件传输 V1 范围：

- 支持单文件双向传输。
- 单文件验收目标为 100MB。
- 支持取消、失败状态和 `sha256` 完整性校验。
- 不支持目录传输和断点续传。
- 文件内容走端到端加密远控数据通道；服务端只记录元数据和审计状态。

第一版不做：

- 4K/144fps 游戏级体验承诺
- 系统音频采集、传输和远端播放
- 摄像头、麦克风远程调用
- 远程命令行
- 远程开机、WOL、智能插座唤醒或带外管理唤醒
- 批量脚本下发
- V1 Core 生产会话录制
- 服务端集中录屏
- 企业 SSO
- 短信验证码作为默认 MFA
- 浏览器主控
- V1 Core 多区域数据驻留承诺

## 5. 关键体验目标

连接：

- 不要求用户开放端口。
- 同局域网优先直连。
- P2P 失败自动 Relay。
- UDP 被封时可以通过 TLS 443 Relay 连接。
- 连接失败必须给出可理解原因。

画面：

- H.264 为默认编码。
- 办公场景优先文字清晰度。
- 弱网时允许降帧率、降分辨率，不允许输入明显排队。
- 媒体能力协商和质量控制必须符合 `docs/spec/20260719193000004_媒体质量控制与能力协商设计.md`。

输入：

- 鼠标移动、点击、滚轮和键盘事件必须低延迟。
- 输入事件优先级高于视频帧和文件传输。
- iOS 必须提供虚拟键盘、快捷键面板和触控手势。
- 中文 IME、文本提交、物理按键和组合键必须按 `docs/spec/20260719193000003_键盘IME与快捷键输入设计.md` 处理。

安全：

- 被控端必须有明显连接状态。
- 被控端必须能一键断开。
- 文件传输和剪贴板必须独立授权。
- 无人值守必须独立开关、加密保存、可审计。
- 隐私屏和本地输入保护必须独立授权、默认关闭、断开后恢复，不得用于隐藏远控。
- 远程重启必须本地提示、可取消、可审计，重启后只能创建新会话。
- 反诈、账号 MFA、风险验证、条件访问和客户端防伪必须符合 `docs/spec/20260719193000001_反诈与滥用防护设计.md`、`docs/spec/20260719190000001_账号MFA与风险验证设计.md`、`docs/spec/20260719190000002_访问控制与条件访问设计.md` 和 `docs/spec/20260719190000004_供应链与客户端防伪设计.md`。
- 设备身份、登录 challenge、设备注册授权、会话密钥和无人值守凭据必须符合 `docs/decision/20260721000000002_登录设备身份与受信任主控设备契约.md`、`docs/spec/20260719171718533_安全与密钥协议设计.md` 和 `docs/spec/20260719171718533_认证与无人值守凭据设计.md`。
- 会话录制和企业区域驻留边界必须符合 `docs/spec/20260719193000005_会话录制与合规审计边界设计.md` 和 `docs/spec/20260719193000006_企业区域路由与数据驻留设计.md`。

## 6. 产品模式

临时协助：

```text
被控端展示设备 ID 和验证码
主控端输入设备 ID 和验证码
服务端创建 pending session 并下发短码 challenge
主控端提交不含验证码明文的 proof
被控端确认
建立远控会话
```

账号内设备确认连接：

```text
用户登录账号
主控端从设备列表选择在线设备
服务端创建 waiting_approval session 并推送确认请求
被控端确认
建立远控会话
```

无人值守：

```text
用户登录账号
设备绑定账号
用户开启无人值守并设置访问凭据
主控端选择设备
服务端校验账号和策略
服务端创建 pending session 并下发无人值守 challenge
主控端提交不含凭据明文的 proof
require_prompt = false 时进入 unattended_verified，并允许开始候选/Relay/密钥交换
require_prompt = true 时进入 waiting_approval 并等待被控端确认
被控端接受后才允许开始候选/Relay/密钥交换
```

`V1 Commercial` 私有化部署：

```text
企业部署 API / Signal / Relay / PostgreSQL / Redis
客户端配置私有服务地址
企业管理员管理成员、设备和审计
按组织配置区域路由和数据驻留
```

完整私有化部署不是 `V1 Core` 发布门禁；`V1 Core` 只要求本地 Docker Compose 能启动必要服务并支持客户端配置服务地址。

## 7. 权限模型

会话权限：

- `remote_desktop`
- `input_control`
- `clipboard`
- `file_transfer`
- `unattended`
- `privacy_screen`
- `block_local_input`

策略位：

- `require_prompt`
- `allow_relay`

说明：

- 产品界面默认展示 7 个用户能力：远程桌面、输入控制、剪贴板、文件传输、无人值守、隐私屏、本地输入保护。
- 服务端有效权限和 `permissions_digest` 使用 9 项模型：7 个用户能力 + `require_prompt` + `allow_relay`。
- `require_prompt` 控制是否必须被控端确认；`allow_relay` 控制是否允许使用 Relay 兜底路径；`privacy_screen` 和 `block_local_input` 必须参与密钥交换绑定。
- `allow_remote_reboot` 是独立高风险策略字段，不加入 V1 的 9 项 `permissions_digest`；远程重启通过 API step-up、设备签名、端点确认和审计控制。

默认策略：

- 临时协助默认需要被控端确认。
- 无人值守默认关闭。
- 剪贴板默认关闭，用户可开启。
- 文件传输默认关闭，用户可开启。
- 隐私屏默认关闭，必须被控端本地允许后才可由主控端请求。
- 本地输入保护默认关闭，必须被控端本地允许并保留安全退出方式。
- 远程重启默认关闭，必须 step-up 和被控端本地允许；临时协助默认要求被控端当次确认。
- 管理员策略可以禁止某些能力。

## 8. 审计要求

必须记录：

- 登录成功和失败
- 设备注册
- 设备注册授权消费、受信任设备建立和撤销
- 账号 session 因 MFA 启停或修改密码被撤销
- 设备在线/离线
- 会话创建、接受、拒绝、取消、连接、断开、失败
- 反诈风险提示、举报、限流和处置
- Relay 使用情况
- 文件传输请求、确认、拒绝、开始和结束
- 文件传输失败和取消
- 剪贴板使用
- 无人值守开启、挑战签发、成功、失败、轮换和关闭
- MFA 因子绑定、禁用、恢复码使用和风险验证
- 条件访问策略命中、拒绝和变更
- 隐私屏启用、关闭、失败和恢复
- 本地输入保护启用、关闭、失败和恢复
- 媒体能力、质量降级和关键帧请求的裁剪状态
- 远程重启请求、取消、执行、设备离线、设备上线、自动恢复一次同意、恢复和失败
- 客户端更新检查、校验失败、发布和撤销
- M8/V2 会话录制策略和录制访问
- M8 区域策略命中、拒绝和 Relay 区域选择
- 策略和权限变更
- 密钥交换失败和 Relay token 拒绝

审计记录至少包含：

- 操作人账号
- 目标设备
- 动作
- 时间
- IP
- User-Agent
- 会话 ID

## 9. 验收标准

第一版必须通过以下账号身份门禁和平台链路：

- 登录第一段不签发 token，finish 必须绑定设备签名、双 nonce、IP、User-Agent、登录请求和协议版本。
- 只有 access token 或攻击者新公钥自签时不得注册设备；有效 grant 必须与设备插入、grant 消费、审计和可选 trusted-device 写入在同一事务提交。
- 无 MFA 设备自动注册但不建立 trust；TOTP trust 最长 30 天、recovery-code trust 默认 24 小时，普通登录和 refresh 不滑动续期。
- 启用 MFA、禁用 MFA 或修改密码成功时，必须原子撤销账号全部 session 和 active trusted devices。

- Windows 被控 -> Windows 主控
- Windows 被控 -> Ubuntu 主控
- Windows 被控 -> iOS 主控
- Ubuntu 被控 -> Windows 主控
- Ubuntu 被控 -> Ubuntu 主控
- Ubuntu 被控 -> iOS 主控

以上 6 条是 OS 家族链路。发布验收必须继续展开为 `docs/plan/20260719170217641_测试方案.md` 中定义的 20 个发布真实远控组合，由 M5 启动、M6/T022V 补齐逐组合证据，并由 M7/T026 汇总为发布门禁；不得只用 6 条 OS 家族链路替代 20 个变体组合。

每条链路至少验证：

- LAN Direct
- UDP P2P
- QUIC Relay
- TLS 443 Relay
- 被控端确认
- 无人值守
- 反诈提示和举报入口
- 中文 IME、文本输入、组合键和断开释放按键
- 媒体能力协商、弱网降级和关键帧请求
- 远程重启后重新上线和新会话恢复
- 主控端断开
- 被控端断开
- 断线重连
- 审计记录

## 10. 非功能指标

第一版目标：

- 1080p 办公场景稳定可用。
- LAN Direct 场景目标帧率不低于 30fps。
- Relay 场景目标帧率不低于 20fps。
- 常规办公场景端到端输入延迟目标小于 120ms。
- Relay 场景端到端输入延迟目标小于 220ms。
- iOS 主控在最低支持真机和 4G/5G 弱网场景下目标帧率不低于 15fps，输入事件仍优先于视频清晰度和文件传输速度。
- 断线重连目标小于 5 秒。
- 文件传输时控制通道不得出现持续 500ms 以上输入排队；采集口径以媒体质量控制设计中的输入排队时延定义为准。
- Relay 可统计流量和会话数。
- 服务端组件可本地 Docker Compose 启动。
- 客户端异常退出后不残留采集和输入控制状态。

这些是 `V1 Core` 工程基线。`V1 Core` 正式发布前必须基于真实机器和网络矩阵重新校准。
