# 键盘 IME 与快捷键输入设计

## 1. 目标

远控输入不能只发送一个笼统的 `key_code`。Windows、Ubuntu Wayland/X11、iOS 虚拟键盘和外接键盘在布局、修饰键、组合键、中文输入法和系统保留快捷键上差异很大。首版必须同时支持“文本输入准确”和“快捷键低延迟”。

目标：

- 区分物理按键、文本提交、IME 组合态和快捷键。
- 中文输入、英文输入、常用组合键和外接键盘可验证。
- 断开、崩溃或重连失败后释放所有按下状态。
- 不记录用户输入文本、按键内容和 IME 组合内容。
- 不承诺绕过系统安全边界。

## 2. 范围

`V1 Core` 必须实现：

- 鼠标、滚轮和触控手势。
- 物理按键 `key_down/key_up/repeat`。
- Unicode 文本提交 `text_commit`。
- 常用快捷键面板。
- iOS 虚拟键盘和外接键盘。
- Windows 主控/被控输入映射。
- Ubuntu Wayland portal 输入和 X11 fallback。
- 中文 IME 基础输入验收。

后置增强：

- 游戏键盘级原始输入。
- 自定义键盘布局编辑器。
- 多语种 IME 深度同步。
- Ctrl+Alt+Del、安全桌面和登录界面控制。

## 3. 输入模式

输入模式：

- `pointer`：鼠标移动、点击、滚轮和触控映射。
- `physical_key`：按物理键或平台扫描码发送，适合快捷键和应用内热键。
- `text_commit`：按 Unicode 文本提交，适合中文、英文和符号输入。
- `ime_composition`：可选组合态展示，首版可只本地显示，不要求远端同步候选窗。
- `shortcut`：经过产品定义的快捷键动作，例如复制、粘贴、切换窗口。

默认规则：

- 普通文本输入优先使用 `text_commit`。
- 快捷键、功能键和修饰键使用 `physical_key` 或 `shortcut`。
- 用户可以在会话窗口切换“文本优先”和“按键优先”。
- 输入事件优先级高于视频帧和文件传输。

## 4. 协议字段

扩展 `input_event` 字段：

- `session_id`
- `event_id`
- `display_id`
- `input_kind`
- `key_event_kind`
- `physical_code`
- `key_code`
- `scan_code`
- `virtual_key`
- `logical_key`
- `text`
- `composition_text`
- `composition_state`
- `modifiers`
- `keyboard_layout`
- `is_auto_repeat`
- `x_norm`
- `y_norm`
- `button`
- `wheel_delta_x`
- `wheel_delta_y`
- `timestamp_epoch_millis`

`input_kind` 取值：

- `mouse_move`
- `mouse_button`
- `mouse_wheel`
- `physical_key`
- `text_commit`
- `ime_composition`
- `shortcut`
- `touch_gesture`
- `release_all_keys`

`key_event_kind` 取值：

- `down`
- `up`
- `repeat`
- `tap`

规则：

- `session_id/event_id` 在线协议固定为标准 UUID 字符串；`physical_code/key_code/scan_code/virtual_key` 使用可选或缺省为 0 的 u32；`modifiers` 固定为 `ctrl/alt/shift/meta/caps_lock` 字符串数组；`wheel_delta_x/wheel_delta_y` 使用有限 f64，缺省为 0。
- `event_id` 必须去重，重复事件不得重复注入。
- `key_code` 首版等于 USB HID Usage ID 的 u32 表示；无法映射时为 0，并通过 `physical_code/scan_code/virtual_key/logical_key` 表达平台信息。接收端不得只信任 `key_code` 跳过平台映射和权限校验。
- `text` 和 `composition_text` 只能在应用层端到端加密业务 payload 中出现。
- `text`、`composition_text`、`logical_key` 的具体字符不得写日志。
- `release_all_keys` 在断开、重连超时、焦点丢失和会话关闭时必须发送或本地执行。
- 没有 `input_control` 权限时必须拒绝所有输入事件。

## 5. 平台映射

Windows 被控端：

- 普通按键优先映射为 `SendInput`。
- 文本提交优先使用 Unicode 输入路径。
- 修饰键状态必须由会话输入管理器统一维护。
- UAC、安全桌面、锁屏和登录界面不承诺绕过。

Ubuntu Wayland 被控端：

- 优先使用 xdg-desktop-portal RemoteDesktop 输入能力。
- portal 不支持的按键或组合键必须返回明确错误或降级。
- 不得绕过 compositor、portal 或系统权限。

Ubuntu X11 被控端：

- 可使用 XTest/uinput 注入。
- 必须维护按键状态，并在断开后释放。
- 键盘布局变化时必须重新上报能力。

iOS 主控端：

- 虚拟键盘普通文字走 `text_commit`。
- 外接键盘快捷键可以走 `physical_key` 或 `shortcut`。
- iOS shell 负责把外接 HID 键盘事件转换为协议 `physical_code` 或 `shortcut`，转换表必须与平台上报的 `keyboard_layouts` 绑定；日志不得记录原始 HID usage 字节或输入内容。
- 工具栏提供常用组合键按钮。
- 横竖屏和键盘弹出时不得遮挡断开入口。

## 6. 快捷键策略

V1 常用快捷键：

- `Ctrl+C`
- `Ctrl+V`
- `Ctrl+X`
- `Ctrl+Z`
- `Ctrl+Y`
- `Alt+Tab`
- `Ctrl+Alt+Delete_reserved`
- `Super/Win`
- `PrintScreen_reserved`

规则：

- `Ctrl+Alt+Delete_reserved` 首版只保留，不承诺跨平台可用。
- 系统保留快捷键如果无法远端注入，必须显示不支持原因。
- 主控端本机快捷键和远端快捷键冲突时，默认优先保护本机断开和退出能力。
- 用户开启“捕获快捷键”时必须有明显状态和退出方式。

## 7. IME 规则

中文输入：

- 首版优先通过主控端 IME 生成最终 Unicode 文本，再用 `text_commit` 发送到被控端。
- 被控端本地 IME 候选窗不作为首版同步目标。
- 被控端应用不支持 Unicode 注入时，客户端必须降级为剪贴板粘贴或提示失败；剪贴板降级必须受 `clipboard` 权限控制并提示用户。

组合态：

- `ime_composition` 可用于主控端本地显示组合态。
- 组合态内容不得进入日志、审计或服务端。
- composition cancel 时不得向被控端提交文本。

布局：

- 客户端能力上报必须包含 `keyboard_layouts`、`input_methods` 和 `supports_text_commit`。
- 布局变化必须通过能力状态更新通知对端。
- 远端布局未知时，快捷键优先使用物理键，文本优先使用 `text_commit`。

## 8. 审计和日志

审计只记录：

- 输入控制开启或关闭。
- 输入权限拒绝。
- 平台输入能力 unsupported。
- `release_all_keys` 恢复结果。

不得记录：

- 文本内容。
- 按键字符。
- IME 组合文本。
- 剪贴板降级时的文本内容。

## 9. 测试要求

必须验证：

- Windows 被控 -> Windows/Ubuntu/iOS 主控、Ubuntu 被控 -> Windows/Ubuntu/iOS 主控输入链路；iOS 只作为主控端，不作为被控端输入注入目标。
- 英文文本输入。
- 中文输入法文本提交。
- 符号和换行输入。
- Ctrl/Cmd 等修饰键组合。
- Alt+Tab 或平台等价快捷键。
- 长按自动重复。
- 焦点切换后不丢修饰键状态。
- 网络断开、会话关闭、主控端崩溃后释放所有按键。
- Wayland 不支持的输入能力返回明确错误。
- iOS 虚拟键盘、快捷键面板、外接键盘和鼠标。
- 日志扫描不包含文本、按键和 IME 内容。
