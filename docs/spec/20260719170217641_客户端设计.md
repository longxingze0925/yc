# 客户端设计

## 0. Mobile MVP 当前优先级

- iOS 首页只优先交付登录、我的设备、一键连接和远控画面。
- 桌面端首阶段只优先交付被控能力与“允许我的设备远程访问”一次开关，桌面主控窗口后置。
- 普通用户固定连接官方托管端点，不显示 API/Signal/Relay 地址或证书指纹。现有服务地址配置只保留为开发调试和后续自建高级入口。
- 远控画面首阶段只保留画面、连接状态、触控、键盘和断开；剪贴板、文件、多屏、重启和隐私屏后置。

## 1. 客户端范围

桌面端（统一客户端模型）：

- Windows 10/11
- Ubuntu Desktop 26.04 LTS x86_64

桌面客户端是同一个软件，登录账号后默认同时具备主控能力和被控能力。被控能力的最终状态由本机用户授权、系统采集权限和远控会话策略共同决定。

iOS：

- 只做主控端。
- 最低支持版本冻结为 iOS 16。
- 如未来提高最低 iOS 版本，必须先补 ADR 并同步产品规格、测试方案和 AI 任务清单。

平台能力：

| 平台 | controller | controlled | 进程模型 |
| --- | --- | --- | --- |
| Windows | 是 | 是 | UI + 托盘 + Service |
| Ubuntu | 是 | 是 | UI + systemd user service，必要时 system service |
| iOS | 是 | 否 | App 进程 |

登录即绑定：

- 桌面客户端在登录前加载或生成设备长期 Ed25519 密钥，完成两段式登录后自动使用一次性 enrollment grant 把当前设备注册到账号"我的设备"。
- 桌面客户端不必区分"主控端登录"和"被控端登录"。
- iOS 客户端按同一 challenge/grant 流程注册为 `controller only` 设备，不出现在"可被连接"列表中；只有本次完成 TOTP/recovery 时才建立受信任主控设备记录。

共同登录流程：

1. 从平台安全存储加载 `device_id`、Ed25519 私钥、公钥及已知 `public_key_id/public_key_version`；本机尚无身份时在提交密码前生成，不得上传私钥。
2. 调用 `POST /v1/auth/login` 提交账号、设备身份、32-byte `client_nonce` 和 `protocol_version`；第一段只接受 challenge 响应，不得把密码正确当作已登录。
3. 按 `required_factors` 收集 TOTP 或恢复码，使用设备私钥和现有 `rctl-api-input-v1` Header 签名 `POST /v1/auth/login/finish`；双 nonce、两个 binding hash 和协议版本必须与第一段一致。
4. `pending_enrollment` 成功后立即使用 token、`device_enrollment_grant` 和同一拟注册私钥签名调用 `POST /v1/devices`；grant 只在短期内存中持有，过期或身份冲突时清除 token/grant 并从登录 challenge 重新开始。
5. 设备注册成功后再展示完整账号设备页和建立 Signal 连接。只有 access token、grant 缺失或设备注册事务失败时，不得把设备显示为已绑定或受信任。

无 MFA 账号仍自动注册设备，但 UI 不得显示为受信任设备。普通登录和 refresh 不得把服务端返回的原 trust 到期时间改写为新的 30 天。

共同能力：

- 登录
- MFA 和高风险操作验证
- 设备注册
- 设备列表
- 发起连接
- 远控会话
- 连接状态
- 一键断开
- 反诈风险提示、举报和拉黑入口
- 键盘、IME、组合键和输入状态恢复
- 媒体质量控制和能力诊断
- 远程重启请求和恢复等待
- 日志和诊断信息
- 安装包和更新签名校验

## 2. 技术栈

核心：

- Rust

Windows/Ubuntu UI：

- Slint + Rust

iOS UI：

- SwiftUI/UIKit

渲染：

- Windows：D3D11 / DirectComposition
- Ubuntu：OpenGL / Vulkan
- iOS：Metal

编解码：

- H.264 第一优先
- Windows：NVENC / QSV / AMF / 软件兜底
- Ubuntu：VAAPI / 软件兜底
- iOS：VideoToolbox 解码；iOS 首版仅作为主控端，不承担被控端编码责任。

输入：

- Windows：SendInput + Unicode 文本提交。
- Ubuntu Wayland：xdg-desktop-portal RemoteDesktop。
- Ubuntu X11：XTest/uinput fallback。
- iOS：虚拟键盘、快捷键面板、外接键盘和鼠标。

## 3. 桌面客户端进程

Windows：

- 用户态 UI 进程。
- 托盘进程。
- Windows Service 支持无人值守。

Ubuntu：

- 用户态 UI 进程。
- systemd user service。
- 必要时提供 system service。

进程原则：

- UI 崩溃不应留下输入控制状态。
- 被控服务退出必须释放采集和输入资源。
- 无人值守服务必须可关闭。

## 4. 桌面 UI

核心页面（统一客户端）：

- 登录：账号 + 密码（含 MFA / 风险验证），登录页明确告知"登录后此设备会自动加入我的设备"。
- 首页：本机设备卡片置顶，展示本机设备 ID、本机临时验证码、本机在线状态、本机是否允许远程连接、无人值守状态、屏幕采集权限、输入控制权限、本机名称。
- 我的设备：列出账号下所有设备，桌面设备按 `controller+controlled` 标记，iOS 按 `controller only` 标记。
- 临时协助：输入对方设备 ID 和一次性验证码。
- 远控会话窗口：主控他人时的画面、工具栏与权限。
- 被控授权与状态：被他人连接时的横幅、授权窗口、断开按钮、隐私屏和本地输入保护开关。
- 文件传输：独立入口，不在会话窗口内堆叠。
- 设置：账号安全、设备管理、无人值守、反诈与举报、媒体质量、键盘/IME 行为、诊断导出。
- 日志/诊断：本地导出，不上传服务端。

设计原则：

- 首页"本机设备"卡片始终可见，避免用户找不到自己的设备 ID 和验证码。
- 工具型界面，信息密度高，避免营销式首页。
- 状态清晰：在线、离线、连接中、被控制中、Relay 中。
- 危险操作必须明确确认。
- 被控端连接中必须有醒目状态条和断开按钮。
- 陌生账号临时协助必须显示风险提示和举报入口。
- 隐私屏和本地输入保护必须有独立开关、状态和错误提示。
- 登录 challenge 过期、设备身份冲突、grant 过期和设备注册失败必须显示可恢复错误，并清理未完成登录的临时状态。
- 启用 MFA 成功后当前 session 会被服务端撤销；客户端必须先解密并确认保存恢复码，再清理旧 token 并重新登录，不得用旧 refresh token 静默恢复。

恢复码交付：

- TOTP start 前生成临时 X25519 密钥对，私钥在平台安全存储中保留到恢复码 ciphertext 成功解密或 delivery 过期。
- TOTP finish 使用稳定 `Idempotency-Key`；响应丢失时以同一账号 session、factor、客户端临时公钥、finish binding 和幂等键重试，且只接受字节一致的既有 ciphertext。
- 使用服务端临时公钥、nonce、响应中的 `created_at_epoch_millis/expires_at_epoch_millis` 和冻结 HKDF/AAD 解密恢复码，不得以客户端本地时间代替 AAD 时间字段；解密后要求用户确认保存。篡改、错误私钥或 delivery 到期时不得显示伪造恢复码，只能在重新登录后执行恢复码轮换。

设计原则：

- 工具型界面，信息密度高，避免营销式首页。
- 状态清晰：在线、离线、连接中、被控制中、Relay 中。
- 危险操作必须明确确认。
- 被控端连接中必须有醒目状态条和断开按钮。
- 陌生账号临时协助必须显示风险提示和举报入口。
- 隐私屏和本地输入保护必须有独立开关、状态和错误提示。

Mobile MVP 默认流程：登录成功后直接显示“我的设备”，点击已开启远程访问的 Ubuntu/Windows 设备后直接进入连接态。不先显示设备 ID、验证码或服务器配置页。

核心页面：

- 登录
- 设备列表
- 连接输入
- 远控画面
- 工具栏
- 虚拟键盘
- 快捷键面板
- 文件传输入口

交互：

- 单指移动鼠标。
- 单击、双击、长按右键。
- 双指滚动。
- 双指缩放画面。
- 三指或工具栏呼出快捷键。
- 支持蓝牙/USB 外接物理键盘、鼠标或触控板。
- 支持横竖屏。

iOS 首版验收必须覆盖：

- 最低支持 iOS 16 真机和当前主版本真机。
- 虚拟键盘输入。
- 快捷键面板。
- 常用触控手势。
- 蓝牙/USB 外接物理键盘、鼠标或触控板。
- 横屏和竖屏切换。

## 8. 会话窗口

必须显示：

- 远程设备名称。
- 连接路径。
- 延迟。
- 帧率。
- 码率。
- 是否 Relay。
- 权限状态。
- 当前会话风控状态，包括风险提示、被举报、被拉黑或受限原因。

必须提供：

- 断开。
- 多屏切换。
- 输入模式切换。
- 剪贴板开关。
- 文件传输入口。
- 隐私屏请求开关。
- 本地输入保护请求开关。
- 媒体质量档位。
- 远程重启请求。
- 举报和拉黑入口。

## 8A. 键盘、IME 和快捷键

输入模式：

- 文本优先：普通文字和中文输入使用 Unicode `text_commit`。
- 按键优先：快捷键、功能键和修饰键使用物理按键事件。
- 快捷键面板：提供复制、粘贴、撤销、切换窗口等常用组合键。

规则：

- 会话断开、重连超时、窗口失焦或客户端崩溃恢复时，必须释放所有按下状态。
- `text`、按键内容和 IME composition 不得写入日志、审计或服务端。
- Ctrl+Alt+Del、安全桌面、锁屏和 Wayland portal 不支持能力必须明确提示。
- 剪贴板降级输入只有在 `clipboard` 权限允许且用户确认时才能使用。

验收以 `docs/spec/20260719193000003_键盘IME与快捷键输入设计.md` 为准。

## 8B. 媒体质量控制

会话窗口必须展示：

- codec。
- 分辨率。
- 帧率。
- 码率。
- RTT、丢包、抖动。
- 编码/解码耗时。
- 硬件加速状态。

质量档位：

- `balanced`
- `text_clear`
- `low_bandwidth`
- `low_latency`

规则：

- H.264 是 V1 必选能力。
- H.265、AV1、4:4:4 和 HDR 只预留，不显示为 V1 可用承诺。
- 弱网时优先保证输入，不允许旧帧堆积。
- 硬编失败必须降级软件编码或降低质量，不得直接崩溃会话。

验收以 `docs/spec/20260719193000004_媒体质量控制与能力协商设计.md` 为准。

## 8C. 文件传输端侧安全

V1 只支持单文件双向传输，不支持目录传输和断点续传。

接收端规则：

- 接收路径必须由接收端用户或客户端安全默认目录选择，不能由发送端指定绝对路径。
- `file_name` 只能作为展示名和默认建议名；保存前必须做平台安全文件名归一化，拒绝路径穿越、绝对路径、空名、控制字符、保留设备名和 Windows/Linux 不兼容非法字符。
- 默认不覆盖同名文件；同名冲突必须生成安全的新文件名或要求接收端明确确认覆盖。
- 写入必须先进入同目录临时文件，完成 `sha256` 校验后再原子落盘；校验失败、取消、网络中断或磁盘不足时必须清理临时文件。
- 接收端不得跟随符号链接、硬链接或快捷方式覆盖任意位置；保存前必须校验最终路径仍在用户选择目录内。
- 写入前必须检查单文件大小上限、剩余空间和目录写权限；不足时拒绝并返回明确错误。
- 文件内容不得进入日志、诊断 ZIP、审计 metadata 或服务端 API。

发送端规则：

- 发送前必须读取文件大小、`sha256` 和展示名，不能发送目录或特殊设备文件。
- Windows/Linux 权限不足、文件被占用或读取中断时必须返回明确错误。

验收以测试方案的文件传输端侧安全矩阵为准。

## 8D. 远程重启

主控端：

- 远程重启按钮默认收起在更多操作中。
- 请求前必须展示高风险确认和 step-up。
- 必须显示等待被控端确认、倒计时、设备离线、设备上线和恢复失败状态。
- 用户必须可以取消等待恢复。

被控端：

- 必须显示重启倒计时、主控端标识、原因、取消按钮和断开按钮。
- 重启前必须释放采集、隐私屏、本地输入保护和输入状态。
- 重启后服务可以自动上线，但不得静默恢复旧业务通道。

验收以 `docs/spec/20260719193000002_远程重启与会话恢复设计.md` 为准。

## 8E. 会话录制边界

V1 Core 不提供生产会话录制。

规则：

- 客户端不得默认录制远控画面。
- QA 截图或录屏证据只能由测试人员显式采集，并按测试方案保存。
- M8/V2 如果实现端点侧录制，必须会话前提示、会话中持续显示状态、加密保存并写访问审计。

验收以 `docs/spec/20260719193000005_会话录制与合规审计边界设计.md` 为准。

## 8F. 隐私屏和本地输入保护

共同规则：

- 默认关闭。
- 被控端必须本地显式允许。
- 主控端只能请求，最终状态以被控端上报为准。
- 平台不支持时必须显示明确错误。
- 会话断开、客户端崩溃或网络超时后必须恢复显示和输入状态。
- `allow_privacy_screen` 或 `allow_block_local_input` 从关闭改为允许前，被控端客户端必须先完成高风险 step-up 校验。
- step-up 确认界面必须展示 challenge 目的、目标设备、发起账号和有效期；用户取消、校验失败或超时不得改变本地允许状态。

Windows：

- 不引入未经签名的内核驱动。
- UAC、安全桌面、锁屏和登录界面不承诺绕过系统边界。
- 没有可靠平台能力时不得把用户态遮蔽宣称为安全级隐私屏。

Ubuntu：

- Wayland 必须尊重 PipeWire 和 xdg-desktop-portal 授权。
- X11 fallback 必须在断开后释放 grab、uinput 和 overlay。
- 不支持的桌面环境必须返回 unsupported。

iOS：

- 只提供主控端请求、状态展示和失败提示。
- 断开入口不得被工具栏、键盘或横竖屏布局遮挡。

## 9. 本地日志

记录：

- 启动和退出。
- 登录状态。
- 信令连接状态。
- 会话状态。
- 采集和编码错误。
- 连接路径变化。
- M8/V2 端点侧录制状态元数据，例如 `recording_id`、录制状态、错误码、`recording_path_hash` 和 `recording_access_log_id`；字段边界以 `docs/spec/20260719193000005_会话录制与合规审计边界设计.md` 的日志、审计和诊断导出边界为准，不得包含录制内容或解密密钥。

不得记录：

- 密码。
- 验证码明文。
- TOTP code。
- 恢复码明文。
- step-up token。
- 私钥。
- release private key。
- reboot resume token。
- recording encryption key。
- 远程重启 reason 自由文本。
- 输入文本、按键内容和 IME 组合内容。
- 剪贴板内容。
- 文件内容。

## 10. 安装包

Windows：

- `.msi` 或 `.exe` 安装器。
- 支持安装 Service。
- 安装包必须签名，更新包必须校验 manifest 签名和 SHA-256。

Ubuntu：

- `.deb`。
- systemd 单元。
- 桌面入口。
- `.deb` 或仓库签名必须可验证。

iOS：

- App Store / TestFlight。
- 使用 Apple 签名链。

更新：

- 客户端必须先验证 update manifest 签名。
- 下载后必须验证 artifact SHA-256。
- 平台安装器签名验证失败时不得继续安装。
- 私有化服务地址必须明显展示，不能伪装官方 SaaS。

## 11. 客户端验收

每个平台至少验证：

- 安装。
- 启动。
- 登录。
- 两段式登录第一段不产生 token，finish 的设备签名、双 nonce、binding、IP/User-Agent 变化和协议版本拒绝路径。
- Ubuntu 桌面验收必须按 Wayland 主路径和 X11 fallback 变体展开。
- 官方/私有服务地址配置和环境标识展示。
- 设备注册。
- pending enrollment 的 grant 自动注册、grant 过期重试、只有 access token 时拒绝、并发/幂等结果和无 MFA 不建立 trust。
- 连接。
- 断开。
- 会话前和会话中的反诈提示、举报、拉黑和风控状态。
- 崩溃恢复。
