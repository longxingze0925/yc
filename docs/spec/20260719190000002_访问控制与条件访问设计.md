# 访问控制与条件访问设计

## 1. 目标

远控会话不能只判断账号是否登录，还必须判断谁、从哪台主控设备、在什么网络和策略条件下访问哪台被控设备。

目标：

- 会话创建前统一计算有效访问策略。
- 支持账号、设备、组织、角色和设备组多层策略。
- 支持允许、拒绝、强制 MFA、强制被控端确认和禁止 Relay。
- 支持独立控制远程重启。
- 支持个人场景的黑名单和受信任设备。
- 支持企业场景的条件访问策略。
- 所有拒绝和策略命中必须可审计。

## 2. 范围

`V1 Core` 必须实现：

- 设备黑名单。
- 被控设备本地权限开关。
- 受信任主控设备。
- 会话有效权限求交集。
- `require_prompt` 和 `allow_relay` 策略。
- 条件访问评估器的服务端边界。

`V1 Commercial/M8` 必须实现：

- 组织、角色和设备组策略下发。
- IP/CIDR allowlist 和 denylist。
- 时间窗口策略。
- 地区策略。
- 组织强制 MFA。
- 管理后台策略审计。

首版不做：

- 基于浏览器主控端的条件访问。
- Android/macOS 设备策略。
- 绕过系统权限的远控能力。

## 4. 决策结果

条件访问策略评估必须返回：

- `access_decision`，取值为 `allow | deny | require_mfa | require_prompt`
- `effective_permissions`
- `permissions_digest`
- `matched_policy_ids`
- `deny_reason`
- `risk_challenge_id`
- `policy_evaluation_id`

反诈与滥用防护结果参与合成时必须提供：

- `anti_abuse_decision`，取值为 `allow | warn_user | cooldown | deny_session`
- `abuse_risk_level`
- `abuse_actions`
- `cooldown_until_epoch_millis`
- `user_warnings`

最终会话准入必须输出统一对象 `session_access_decision`：

- `session_access_decision`，取值为 `allow | warn_user | require_prompt | require_mfa | cooldown | deny_session`
- `access_decision`
- `anti_abuse_decision`
- `effective_permissions`
- `permissions_digest`
- `matched_policy_ids`
- `deny_reason`
- `risk_challenge_id`
- `policy_evaluation_id`
- `abuse_risk_level`
- `abuse_actions`
- `cooldown_until_epoch_millis`
- `user_warnings`

规则：

- `access_decision = deny` 优先于所有允许项，并合成为 `session_access_decision = deny_session`。
- `access_decision = require_mfa` 必须在会话创建前完成，不能在业务通道建立后补。
- `access_decision = require_prompt` 只表示必须被控端确认，不代表拒绝。
- `allow_relay = false` 时不得分配 Relay token。
- `allow_remote_reboot = false` 时不得创建远程重启请求。
- 策略结果必须写入会话和审计上下文。
- 客户端不得自行计算最终权限或 `permissions_digest`。
- 条件访问结果必须与反诈结果合成为统一 `session_access_decision` 后再创建会话。
- 最终枚举固定为 `allow | warn_user | require_prompt | require_mfa | cooldown | deny_session`。
- 合成优先级固定为 `deny_session` 或 `access_decision = deny` > `cooldown` > `require_mfa` > `require_prompt` > `warn_user` > `allow`。
- `warn_user` 不改变允许结果，但必须进入 `user_warnings` 并推送到主控端和被控端 UI。
- `disable_unattended`、`suspend_device`、`suspend_account` 和 `relay_quarantine` 是收紧动作，必须进入 `abuse_actions` 并写审计。

## 5. 权限模型

会话权限 canonical 字段顺序固定为：

```text
remote_desktop
input_control
clipboard
file_transfer
unattended
privacy_screen
block_local_input
require_prompt
allow_relay
```

规则：

- 所有字段都是 boolean。
- `remote_desktop/input_control/clipboard/file_transfer/unattended/privacy_screen/block_local_input/allow_relay` 安全缺省为 `false`。
- `require_prompt` 安全缺省为 `true`。
- `permissions_digest = SHA256(canonical_permissions)`。
- canonical 编码使用协议设计中的长度前缀规则。
- 会话密钥交换和 HKDF 必须绑定该 `permissions_digest`。
- 权限变化后旧应用层会话密钥必须失效。
- 权限变化后，依赖旧权限上下文完成的高风险 step-up 不得继续适用于远程重启、隐私屏授权、本地输入保护授权等新动作；服务端必须重新验证 step-up 或写入 `step_up_revalidated` 审计。
- 远程重启请求必须校验 step-up 未过期，且 `step_up_verified_at_epoch_millis >= max(permissions_digest_last_changed_at_epoch_millis, allow_remote_reboot_last_changed_at_epoch_millis, policy_evaluated_at_epoch_millis)`。

## 6. 策略层级

策略层级：

```text
系统默认
账号策略
组织策略
设备组策略
设备本地策略
角色权限
一次性会话请求
```

能力字段：

- `allow_remote_desktop`
- `allow_input_control`
- `allow_clipboard`
- `allow_file_transfer`
- `allow_unattended`
- `allow_privacy_screen`
- `allow_block_local_input`
- `allow_relay`

高风险动作字段：

- `allow_remote_reboot`

能力字段语义：

- 设备本地策略使用 boolean。
- 组织和设备组策略使用 `inherit | allow | deny` 三态。
- 角色权限使用 boolean。
- `deny` 或角色 `false` 优先。
- `allow` 只表示该层不阻断，不能越过设备本地关闭项。
- `allow_remote_reboot` 不加入 V1 的 9 项 `permissions_digest`，作为 API 高风险动作策略单独评估。
- `allow_remote_reboot` 从 false 改 true 必须先完成高风险 step-up 并写审计；从 true 改 false 不需要 step-up。

确认字段：

- `require_prompt` 使用 `inherit | require | no_prompt` 三态。
- 任一层 `require` 时最终必须确认。
- 角色 `can_bypass_prompt = false` 时最终必须确认。
- `no_prompt` 不能越过设备本地强制确认。

## 7. 条件访问

条件类型：

- IP/CIDR allowlist。
- IP/CIDR denylist。
- 地区 allowlist。
- 地区 denylist。
- 时间窗口。
- 反诈处置状态。
- 受信任主控设备要求。
- MFA 要求。
- Relay 使用限制。
- 文件传输大小限制。
- 剪贴板方向限制。

动作：

- `deny_session`
- `require_mfa`
- `require_prompt`
- `disable_relay`
- `disable_clipboard`
- `disable_file_transfer`
- `disable_privacy_screen`
- `disable_block_local_input`
- `disable_remote_reboot`

评估规则：

- denylist 优先于 allowlist。
- 时间窗口不匹配时拒绝或强制确认，按策略配置执行。
- IP、地区和 ASN 只能作为风险输入，不能作为唯一身份凭据。
- 地区判断失败时按高风险处理。
- 风险验证通过后仍必须执行设备签名和会话权限校验。

## 8. API 设计

会话创建：

- `POST /v1/sessions` 必须调用策略评估器。
- 策略拒绝时不得创建可建链会话。
- 需要 MFA 时返回 `step_up_required`，完成后必须重新评估策略。
- 策略结果必须写入 `policy_evaluations`，并把 `policy_evaluation_id`、`sessions.permissions`、`sessions.permissions_digest` 和审计绑定起来。

管理接口：

```text
GET  /v1/access-policies
POST /v1/access-policies
PATCH /v1/access-policies/{access_policy_id}
DELETE /v1/access-policies/{access_policy_id}
POST /v1/access-policies/{access_policy_id}/assignments
DELETE /v1/access-policy-assignments/{assignment_id}
GET  /v1/devices/{device_id}/access-rules
PATCH /v1/devices/{device_id}/access-rules
```

M8 管理后台必须覆盖以上能力。`V1 Core` 可以先只暴露设备黑名单、受信任设备和本地权限开关。

- `device_access_rule_id`
- `controlled_device_id`

- `rule_type`
- `reason`
- `created_by_account_id`
- `created_at_epoch_millis`
- `expires_at_epoch_millis`

字段规则：

- `conditions` 和 `effects` 可以用 JSONB 起步，但必须有服务端 schema 校验。
- `access_policies.scope_type` 首版固定集合为 `account`、`organization`、`device_group`、`device`。
- `access_policies.status` 首版固定集合为 `active`、`disabled`、`deleted`。
- `policy_evaluation_id` 由服务端生成，记录创建后不可修改；策略、权限、反诈输入或 step-up 状态变化时必须生成新 ID。
- `request_type = session_create` 且会创建会话记录时，api-server 必须先预分配 `session_id`，再把同一 ID 写入 `policy_evaluations` 和 `sessions`；策略在创建会话前拒绝时，`session_id` 可以为空，但必须写入审计和裁剪后的请求摘要。
- `sessions.policy_evaluation_id`、远程重启请求和 `action = access_policy_evaluated` 审计必须引用同一评估记录，不能用异步审计替代 `policy_evaluations`。
- `access_policy_assignments` 的删除必须是软删除或禁用；已用于会话、策略评估或审计的 assignment 关系必须可追溯。
- `access_policy_assignments.target_type` 首版固定集合为 `account`、`organization`、`role`、`device_group`、`device`。
- `access_policy_assignments.status` 首版固定集合为 `active`、`disabled`、`deleted`。
- `rule_type` 首版固定集合为 `allow`、`deny`、`trusted`。
- 黑名单不得被普通 `allow` 策略覆盖。
- 过期规则不得参与新会话评估。

## 10. 审计

必须新增或支持审计动作：

- `access_policy_created`
- `access_policy_updated`
- `access_policy_deleted`
- `access_policy_assigned`
- `access_policy_unassigned`
- `access_policy_evaluated`
- `access_policy_denied`
- `device_access_rule_updated`

审计 metadata 允许记录：

- `matched_policy_ids`
- `policy_evaluation_id`
- `decision`
- `deny_reason`
- `old_permissions_digest`
- `new_permissions_digest`

审计 metadata 禁止记录：

- 完整 token。
- 密码、验证码、MFA code。
- 剪贴板内容。
- 文件内容。

## 11. 测试要求

必须验证：

- 黑名单命中时拒绝会话。
- 设备本地关闭能力时，组织策略不能重新开启。
- 组织或设备组 `deny` 优先。
- `require_prompt=require` 强制被控端确认。
- 角色 `can_bypass_prompt=false` 时不能免确认。
- `allow_relay=false` 不签发 Relay token。
- 条件访问要求 MFA 时，未完成 step-up 不创建可建链会话。
- 反诈处置要求冷却或拒绝时，不创建可建链会话。
- IP/CIDR denylist 命中时拒绝并写审计。
- M8 区域策略命中时按企业区域驻留文档执行，地区诊断不能作为身份凭据。
- 时间窗口外访问按策略拒绝或要求确认。
- 权限变更后 `permissions_digest` 变化，旧会话密钥失效。
- 客户端篡改 requested permissions 不能扩大最终权限。
