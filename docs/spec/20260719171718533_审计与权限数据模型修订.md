# 审计与权限数据模型修订

## 1. 目标

现有初始迁移是 P1 骨架，不足以覆盖完整产品规格。本文记录补齐审计、权限、无人值守和登录态模型的修订依据；主数据库设计已经吸收这些要求。后续开发不得直接以现有 `0001_initial_schema.sql` 作为最终数据库结构。

## 2. 权限模型

会话权限：

- `remote_desktop`
- `input_control`
- `clipboard`
- `file_transfer`
- `unattended`
- `privacy_screen`
- `block_local_input`
- `require_prompt`
- `allow_relay`

`permissions_digest` 计算必须引用协议设计中的 canonical 编码：固定字段顺序为上述 9 项，编码为 `field_name_len || field_name || value_len || value`，boolean 使用 `value_len = 1 || bool_u8`。计算前服务端必须物化全部字段，`allow_*` 安全缺省为 `false`，`require_prompt` 安全缺省为 `true`。

设备策略：

- 是否允许被远控。
- 是否允许无人值守。
- 是否允许剪贴板。
- 是否允许文件传输。
- 是否允许隐私屏。
- 是否允许本地输入保护。
- 是否允许 Relay。
- 是否允许远程重启。
- 是否强制被控端确认。

首版组织策略模型：

- 组织级策略。
- 设备组策略。
- 成员角色策略。
- 管理员策略只能收紧设备本地策略，不能放宽设备本地禁止项。
- 组织和设备组的 `allow_*` 能力字段必须支持 `inherit/allow/deny` 三态，拒绝优先。
- `require_prompt` 必须使用 `inherit/require/no_prompt` 三态；`require` 优先，`no_prompt` 不得越过设备本地强制确认或角色不允许免确认。
- 设备必须有明确组织边界；个人设备自动归属个人默认组织，团队设备通过 `organization_devices` 或设备主组织字段归属组织。

## 6. device_policies

用途：

- 保存设备级权限开关。

建议字段：

- `device_id`
- `allow_remote_desktop`
- `allow_input_control`
- `allow_clipboard`
- `allow_file_transfer`
- `allow_unattended`
- `allow_privacy_screen`
- `allow_block_local_input`
- `require_prompt`
- `allow_relay`
- `allow_remote_reboot`
- `updated_at_epoch_millis`

规则：

- 默认最小权限。
- 远程重启默认关闭，`allow_remote_reboot` 是独立高风险动作策略字段，不加入 V1 的 9 项 `permissions_digest`。
- 管理员策略通过 `organization_policies` 和 `device_group_policies` 覆盖设备策略。
- 最终权限按设备策略、组织策略、设备组策略和角色权限求交集，拒绝优先。
- 设备本地策略不能放宽管理员已经禁止的能力。
- 组织和设备组的 `allow_*` 能力字段使用 `inherit/allow/deny` 三态；`deny` 优先，`allow` 不能越过设备本地关闭项。
- `require_prompt` 使用 `inherit/require/no_prompt` 三态；任一层 `require` 或角色 `can_bypass_prompt = false` 时，最终 `require_prompt` 必须为 `true`。

权限 digest：

- 会话权限必须定义 canonical 字段顺序：`remote_desktop`、`input_control`、`clipboard`、`file_transfer`、`unattended`、`privacy_screen`、`block_local_input`、`require_prompt`、`allow_relay`。
- 服务端计算 digest 前必须物化全部字段，不允许缺字段参与计算。
- 安全缺省：`remote_desktop/input_control/clipboard/file_transfer/unattended/privacy_screen/block_local_input/allow_relay` 为 `false`，`require_prompt` 为 `true`。
- canonical 字段顺序以上述 9 项为唯一权威；编码规则与协议设计的确定性长度前缀编码一致：`field_name_len || field_name || value_len || value`，boolean 使用 `value_len = 1 || bool_u8`。
- `permissions_digest = SHA256(canonical_permissions)`。
- `sessions` 必须保存 `permissions_digest`，用于 signed key exchange 和 HKDF。
- 角色参与会话权限求交集时，必须由 `role_permissions` 提供会话能力字段和 `can_bypass_prompt`。

## 9. 审计字段

每条审计建议包含：

- `audit_id`
- `actor_type`
- `actor_account_id`
- `actor_device_id`
- `actor_role`
- `actor_service`
- `target_device_id`
- `session_id`
- `resource_type`
- `resource_id`
- `action`
- `result`
- `reason`
- `metadata`
- `actor_account_snapshot`
- `actor_device_snapshot`
- `target_device_snapshot`
- `ip_address`
- `user_agent`
- `request_id`
- `created_at_epoch_millis`

`actor_type` 规则：

- `anonymous`：登录失败、未认证请求等无可信账号和设备身份的事件，`actor_account_id`、`actor_device_id`、`actor_role` 和 `actor_service` 为空。
- `account`：已认证账号但未绑定设备请求签名的账号级操作，`actor_account_id` 必填，`actor_device_id`、`actor_role` 和 `actor_service` 为空。
- `device`：用户设备发起，`actor_account_id` 和 `actor_device_id` 必填，`actor_service` 为空；`actor_role` 表示会话角色，只能是 `controller | controlled`，会话、文件传输、连接状态和远程重启等会话内设备动作必须填写 `actor_role`，设备注册和设备状态变更等非会话设备动作为空。
- `service`：服务间调用或服务账号上报，`actor_service` 必填，`actor_account_id`、`actor_device_id` 和 `actor_role` 为空。
- `system`：超时、调度器或系统策略自动关闭，`actor_account_id`、`actor_device_id`、`actor_role` 和 `actor_service` 为空。

专项 metadata 规则：

- `device_public_key_rotated.metadata` 固定包含 `old_public_key_id`、`old_public_key_version`、`old_public_key_fingerprint`、`new_public_key_id`、`new_public_key_version`、`new_public_key_fingerprint`、`revoked_at_epoch_millis`、`rotation_reason` 和 `step_up_challenge_id`。
- `device_public_key_revoked.metadata` 固定包含 `old_public_key_id`、`old_public_key_version`、`old_public_key_fingerprint`、`revoked_at_epoch_millis`、`revocation_reason` 和 `affected_session_ids_hash`。
- `capability-events` 必须映射到固定审计动作；未知 event_type 拒绝。metadata 只允许保存状态、错误码、能力摘要 hash、质量档位、统计摘要、确认设备 ID 和时间戳，不得保存 E2EE payload 明文。

不得记录：

- 密码。
- 验证码明文。
- refresh token 明文。
- MFA code。
- 恢复码明文。
- step-up token。
- 私钥。
- release private key。
- reboot resume token。
- recording encryption key。
- 会话密钥。
- 输入文本、按键内容和 IME 组合内容。
- 剪贴板内容。
- 文件内容。

删除策略：

- 删除账号或设备不得清空审计归因。
- 审计表必须保留不可变 ID 和必要 snapshot 字段。
- 物理迁移中外键删除策略优先使用 `RESTRICT/NO ACTION`；如使用 `SET NULL`，也必须保证 snapshot 可追溯。

## 10. 迁移策略

当前仓库已有：

```text
infra/migrations/0001_initial_schema.sql
```

定稿前处理方式：

- 如果数据库尚未被任何共享环境、测试环境或生产环境使用，可以重写 `0001_initial_schema.sql` 使其匹配定稿模型。
- 如果数据库已经被任何共享环境使用，必须新增 `0002_*` 迁移。
- 生产或共享数据库迁移必须单独确认。

当前阶段不直接修改迁移文件，避免文档审查阶段改变数据库结构。

开发恢复后的 Schema Freeze：

- 必须先确认 `0001_initial_schema.sql` 是否已经被共享环境使用。
- 未被任何共享环境、测试环境或生产环境使用时，优先重写 `0001_initial_schema.sql`，减少早期迁移碎片。
- 已被共享环境使用时，新增 `0002_audit_permission_model.sql` 或同等语义迁移。
- Schema Freeze 必须输出 `0001_initial_schema.sql` 与最终逻辑模型的 delta 清单。
- delta 清单的权威口径以 `docs/spec/20260719170217641_数据库设计.md` 和 `infra/migrations/README.md` 为准；本修订文档不再维护重复字段清单，避免遗漏。
- delta 清单至少必须覆盖最终完整 `sessions.status` 集合、最终完整 `session_events.event_type` 和关键字段、9 项 `permissions_digest` canonical 权限集合、`sessions.permissions_digest_last_changed_at_epoch_millis`、`sessions.policy_evaluation_id`、`sessions.relay_token_epoch`、`policy_evaluations`、`connection_candidates` 表不包含 `candidate_token`、`candidate_token_binding_hash` 和 token 过期时间字段；`connection_candidates.observe_result_id`、账号 MFA 表、`verification_codes.challenge_status`、`account_risk_challenges.device_id/operation_binding_hash/attempts_remaining/consumed_at_epoch_millis`、反诈与滥用表、条件访问表、`access_policy_assignments.status/disabled_at_epoch_millis/deleted_at_epoch_millis/created_by_account_id`、隐私保护本地设置表和本地允许项 step-up 字段、远程重启请求表、远程重启 reason hash、远程重启 `mode = normal | safe_mode_reserved` CHECK、`api_request_hash_status` 对应协议 `request_status = pending | accepted` 的列注释和 CHECK、`remote_reboot_requests.policy_evaluation_id` 强 FK、`reboot_resume_token_id` 唯一索引、远程重启历史查询索引、自动恢复一次同意、`consent_revoked_at_epoch_millis/consent_revoked_by_actor_type/consent_revoked_reason`、`reboot_resume_token_id/reboot_resume_token_secret_hash/reboot_resume_token_consumed_at_epoch_millis/reboot_resume_token_invalidated_at_epoch_millis/reboot_resume_token_invalidation_reason` 和一次性消费字段、文件传输方向、被控端确认和取消归因字段、客户端发布表、manifest 权威字段、更新阶段事件字段、CI/service 发布者字段、审计 `actor_type/actor_role/actor_service/resource_type/resource_id/metadata` 字段、actor CHECK 约束和 Relay token 撤销所需短期状态。
- delta 清单必须显式列出 V1 Core 固定枚举 CHECK：`account_mfa_factors.factor_type/status`、`account_risk_challenges.purpose/risk_level/status`、`trusted_controller_devices.trust_level`、`access_policies.scope_type/status`、`access_policy_assignments.target_type/status`、`device_access_rules.rule_type`、`client_release_channels.scope_type/status`、`client_release_artifacts.status`、`client_update_checks.event_type`。
- `allow_remote_reboot` 是独立高风险策略字段，不纳入 V1 的 9 项 `permissions_digest`；M8/V2 区域驻留和会话录制预留表不纳入 V1 Core 必建门禁，除非明确提前企业化或录制能力。
- 提前实现企业区域驻留或生产录制时，必须先升级 Schema Freeze 范围并额外冻结 `organization_region_policies.cross_region_fail_policy`、`region_catalog.status`、`object_storage_locations.purpose/status`、`session_recording_policies.status` 和 `session_recordings.status`。
- Schema Freeze 结果必须同步更新 `docs/spec/20260719170217641_数据库设计.md` 和 `infra/migrations/README.md`。
- Schema Freeze 完成前，不得开始依赖最终权限、无人值守和审计模型的服务端业务实现。
