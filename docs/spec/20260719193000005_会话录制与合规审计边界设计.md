# 会话录制与合规审计边界设计

## 1. 目标

会话录制是企业合规能力，但它会直接影响隐私、端到端加密和存储合规。首版 `V1 Core` 不做产品化会话录制；测试中为证明画面非空而保存的截图或录屏属于 QA 证据，不等同于生产会话录制功能。

目标：

- 明确 V1 Core 不做生产会话录制。
- 保持 Relay/API/Signal 不具备业务明文解密能力。
- 为 M8/V2 企业合规录制预留安全边界。
- 区分 QA 证据、用户主动录制和企业策略录制。
- 所有未来录制必须显式提示、可审计、加密保存和可配置留存。

## 2. 范围

`V1 Core`：

- 不提供生产会话录制。
- 不提供服务端集中录屏。
- 允许测试人员在验收环境保存截图或录屏证据。
- QA 证据必须按测试方案保存，不能默认上传到生产服务。

`V1 Commercial/M8` 或 V2 可选：

- 端点侧会话录制。
- 企业策略要求录制。
- 录制文件加密保存。
- 录制访问审批和播放审计。
- 录制留存、删除和导出。

禁止：

- Relay/API/Signal 解密视频帧、输入事件、剪贴板内容或文件分片来录制。
- 静默录制。
- 不提示被控端用户的企业录制。
- 录制按键明文、剪贴板内容或文件内容，除非未来有独立合规设计和明确授权。

## 3. 边界定义

QA 证据：

- 仅用于开发、测试和发布验收。
- 由测试人员显式采集。
- 保存到 `docs/report/**` 或受控测试证据目录。
- 不作为产品功能对用户开放。

用户主动录制：

- 由主控端或被控端用户主动开始。
- 双方必须可见。
- 默认只录制远控画面和必要元数据。
- 需要单独授权和审计。

企业策略录制：

- 由组织策略要求。
- 会话开始前必须告知双方。
- 被控端必须显示录制状态。
- 访问录制文件必须有管理员权限、MFA step-up 和审计。

## 4. 加密和存储

未来实现原则：

- 录制只能在端点侧生成。
- 端点侧从本地已解密画面生成录制文件，Relay/API/Signal 仍不能解密业务通道。
- 录制文件上传前必须使用独立 `recording_encryption_key` 加密。
- `recording_encryption_key` 不得等同于远控应用层会话密钥。
- 录制文件存储在对象存储时，服务端只保存密文和元数据。
- 下载、播放和导出必须记录访问审计。

密钥管理：

- V1 不实现。
- M8/V2 必须先选择组织托管密钥、企业自管密钥或客户端本地导出方案。
- M8 进入生产录制编码前必须先完成二次冻结决策，决策结果只能是 `disabled` 或 `implement`。
- 决策为 `implement` 时，必须冻结密钥管理、存储区域、留存删除、播放下载授权、失败策略、Schema Freeze 范围和发布验收项；未冻结前不得实现生产录制。

## 5. 产品提示

未来录制 UI 必须满足：

- 会话开始前显示是否要求录制。
- 会话中持续显示录制状态。
- 被控端本地状态条显示录制状态。
- 录制失败必须告知双方。
- 用户主动录制必须有开始、暂停、停止和保存状态。

不得：

- 把录制状态藏在菜单深处。
- 用录制替代审计日志。
- 录制未授权的摄像头、麦克风、剪贴板或文件内容。

## 6. 数据模型

`V1 Core` 不要求建表。

M8/V2 预留逻辑表：

- `session_recording_policies`
- `session_recordings`
- `session_recording_access_logs`

`session_recording_policies` 关键字段：

- `recording_policy_id`
- `organization_id`
- `scope_type`
- `scope_id`
- `mode`
- `retention_days`
- `encryption_mode`
- `status`
- `created_by_account_id`
- `updated_at_epoch_millis`

`session_recordings` 关键字段：

- `recording_id`
- `session_id`
- `organization_id`
- `created_by_device_id`
- `recording_side`
- `status`
- `object_url`
- `storage_location_id`
- `object_sha256`
- `encrypted_key_ref`
- `started_at_epoch_millis`
- `ended_at_epoch_millis`
- `expires_at_epoch_millis`

规则：

- M8/V2 录制启用时，`session_recording_policies.status` 固定集合为 `active`、`disabled`。
- M8/V2 录制启用时，`session_recordings.status` 固定集合为 `recording`、`completed`、`failed`、`deleted`。
- M8/V2 启用端点侧录制时，`storage_location_id` 必须指向组织区域策略允许的位置，并与留存策略一起写审计。

`session_recording_access_logs` 关键字段：

- `recording_access_log_id`
- `recording_id`
- `actor_account_id`
- `action`
- `reason`
- `created_at_epoch_millis`

规则：

- 这些表不纳入 V1 Core 的 Schema Freeze 必建项。
- 如果 M8 决定提前做录制，必须先升级本文件、数据库设计、服务端设计、客户端设计、测试方案和 AI 任务清单，并在 `T027B0` 冻结决策后才能进入实现。

## 7. 审计

M8/V2 必须新增或支持审计动作：

- `recording_policy_created`
- `recording_policy_updated`
- `recording_started`
- `recording_stopped`
- `recording_failed`
- `recording_uploaded`
- `recording_deleted`
- `recording_played`
- `recording_downloaded`
- `recording_access_denied`

审计 metadata 允许记录：

- `recording_id`
- `recording_policy_id`
- `recording_side`
- `duration_seconds`
- `object_sha256`

禁止记录：

- 录制文件明文内容。
- 录制解密密钥。
- 剪贴板内容。
- 输入文本。
- 文件内容。

## 7A. 日志、审计和诊断导出边界

客户端日志：

- V1 Core 禁止记录任何录制内容。
- M8/V2 启用端点侧录制时，只允许记录 `recording_id`、录制状态、错误码、`recording_path_hash`、`recording_access_log_id` 等元数据。
- 客户端日志不得记录录制文件明文、录制解密密钥、剪贴板内容、输入文本或文件内容。

录制元数据：

- 可以保存 `recording_id`、`session_id`、`recording_side`、`object_sha256`、`encrypted_key_ref`、`storage_location_id` 和访问审计 ID。
- `encrypted_key_ref` 只能是密钥引用或包裹后的密钥标识，不得是可直接解密的明文 key。

诊断导出：

- 默认本地导出，不自动上传服务端。
- 默认不包含录制文件、录制解密 key、剪贴板内容、输入文本或文件内容。
- 可以包含录制 ID、状态、错误码和访问审计 ID，供排障关联。

## 8. 测试要求

V1 Core 必须验证：

- 产品功能中没有默认开启会话录制。
- Relay/API/Signal 无法解密业务明文。
- QA 截图或录屏证据只在测试流程中显式生成。
- 发布验收报告区分 QA 证据和生产录制能力。

M8/V2 如实现，必须额外验证：

- 会话开始前录制提示可见。
- 被控端会话中录制状态持续可见。
- 录制文件加密保存。
- 未授权账号不能播放或下载录制。
- 播放、下载、删除都写访问审计。
- 留存到期按策略删除或冻结。
- 录制加密 key 不得出现在客户端日志、诊断导出或审计 metadata 中。
