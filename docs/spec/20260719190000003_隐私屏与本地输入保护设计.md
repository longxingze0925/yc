# 隐私屏与本地输入保护设计

## 1. 目标

隐私屏和本地输入保护用于防止远控过程中本地旁观者看到敏感内容或本地键鼠误操作影响会话。它们也是高风险能力，必须显式授权、明显提示、可恢复、可审计。

目标：

- `privacy_screen` 和 `block_local_input` 作为独立会话权限。
- 默认关闭。
- 被控端本地必须可见当前处于远控状态。
- 本地用户必须有安全退出方式。
- 断开、崩溃、网络失败后必须恢复显示和输入状态。
- 不把隐私屏实现成隐藏远控。

## 2. 能力定义

`privacy_screen`：

- 尝试遮蔽或保护被控端物理屏幕显示内容。
- 只能在被控端本地允许、策略允许且会话权限允许时启用。
- 平台不支持时必须返回 `unsupported_privacy_screen`，不得伪装成功。

`block_local_input`：

- 尝试阻止被控端本地鼠标、键盘输入影响远控会话。
- 必须保留本地安全退出通道。
- 平台不支持或权限不足时必须返回 `unsupported_local_input_block`。

二者关系：

- 可以单独启用。
- `privacy_screen` 不自动等于 `block_local_input`。
- `block_local_input` 不自动等于 `privacy_screen`。
- 二者都必须进入 `permissions_digest`。

## 3. 产品规则

默认规则：

- 默认关闭。
- 每台被控设备必须本地显式开启允许项。
- 临时协助默认不允许隐私屏和本地输入锁。
- 无人值守可以按设备本地策略允许，但开启能力必须审计。
- 企业策略只能收紧，不能远程绕过被控端本地关闭项。
- 首版要求在会话创建、权限授予或被控端本地安全设置变更前完成高风险 step-up；运行时开关请求只校验会话权限和被控端本地状态。
- 完成 step-up 只表示会话级权限或本地允许项变更可继续处理，最终是否启用仍以运行时 `device_local_security_settings.allow_*` 和平台实际结果为准；step-up 不得绕过本地关闭项。
- 被控端本地 `allow_privacy_screen` 或 `allow_block_local_input` 从 false 改 true 时，step-up challenge 的 `purpose` 必须分别绑定 `allow_privacy_screen` 或 `allow_block_local_input`，`operation_binding_hash` 必须绑定目标设备、目标字段、新值、请求 ID、调用路径和过期时间；purpose 不匹配、challenge 已消费或已过期时不得改变本地允许状态。

被控端提示：

- 连接中必须有明显状态提示。
- 启用隐私屏或本地输入保护时必须显示更高等级状态。
- 被控端必须提供一键断开。
- 如果本地输入被锁，仍必须提供预留安全退出方式，例如系统托盘、服务热键、物理电源/锁屏恢复路径或平台等价能力。

禁止：

- 隐藏运行远控。
- 静默开启隐私屏。
- 静默锁定本地输入。
- 在平台不支持时显示已保护。
- 使用隐私屏绕过系统权限弹窗、UAC、安全桌面或 Wayland portal 授权。

## 4. 会话状态

隐私保护状态：

```text
inactive
requesting
active
restoring
failed
unsupported
```

流程：

```text
1. 主控端请求启用 privacy_screen 或 block_local_input。
2. 被控端本地策略和服务端有效权限都允许。
3. 被控端进入 requesting 并执行平台能力检查。
4. 平台执行成功后进入 active，并向双方推送状态。
5. 会话断开、用户关闭、策略撤销或平台异常时进入 restoring。
6. 恢复成功后进入 inactive；失败进入 failed 并要求本地明显提示。
```

恢复触发：

- 主控端关闭。
- 被控端关闭。
- 会话断开。
- 远程重启执行前。
- 断线重连超时。
- 客户端崩溃恢复 watchdog 触发。
- 被控端用户使用安全退出方式。
- 服务端策略撤销。
- 操作系统切换到不支持的桌面状态。

## 5. 平台设计

Windows：

- `block_local_input` 优先使用用户态可恢复方案，不引入未经签名的内核驱动。
- 涉及安全桌面、UAC、锁屏和登录界面时不承诺绕过系统边界。
- `privacy_screen` 如果没有可靠的签名显示驱动或系统支持，只能作为用户态遮蔽体验，不能宣称安全级隐私屏。
- 启用失败必须降级为明确错误，不得继续显示已保护。

Ubuntu Wayland：

- 必须尊重 PipeWire 和 xdg-desktop-portal 授权。
- 如果桌面环境不支持隐私屏或本地输入锁，必须返回 unsupported。
- 不得绕过 compositor、portal 或系统权限。

Ubuntu X11：

- 可使用 X11 overlay、XGrab、XTest/uinput 等受控方案。
- 断开后必须释放 grab、uinput 和 overlay。
- X11 下也必须提供本地安全退出方式。

iOS 主控端：

- 只提供请求开关、状态展示和错误提示。
- 不作为被控端实现隐私屏。
- 横竖屏、外接键盘和鼠标状态不能遮挡断开入口。

## 6. 协议消息

新增业务消息类型：

- `privacy_mode_request`
- `privacy_mode_state`
- `privacy_mode_restore`

`privacy_mode_request` 字段：

- `session_id`
- `request_id`
- `mode`
- `enabled`
- `reason`
- `timestamp_epoch_millis`

`mode` 取值：

- `privacy_screen`
- `block_local_input`

`privacy_mode_state` 字段：

- `session_id`
- `mode`
- `state`
- `platform_status`
- `error_code`
- `timestamp_epoch_millis`

规则：

- 没有对应权限时必须拒绝 request。
- request 和 state 都走应用层端到端加密业务通道。
- 首版运行时 `privacy_mode_request` 不额外调用服务端 step-up API；step-up 结果必须已经体现在策略评估、会话权限和 `permissions_digest` 中。
- 如果未来要求每次运行时启用都 step-up，必须先新增 API request/hash/过期/端点校验设计，不能让服务端明文解析 E2EE payload。
- 服务端只记录审计元数据，不接收本地屏幕内容或输入内容。
- 状态变更必须写会话事件或审计。

## 7. 数据和权限

会话权限新增：

- `privacy_screen`
- `block_local_input`

设备策略新增：

- `allow_privacy_screen`
- `allow_block_local_input`

组织、设备组和角色策略新增：

- `allow_privacy_screen`
- `allow_block_local_input`

需要纳入 Schema Freeze 的逻辑表：

- `device_local_security_settings`

`device_local_security_settings` 关键字段：

- `device_id`
- `allow_privacy_screen`
- `allow_block_local_input`
- `local_escape_hint_enabled`
- `privacy_screen_supported`
- `block_local_input_supported`
- `last_capability_probe_at_epoch_millis`
- `last_allow_step_up_challenge_id`
- `last_allow_step_up_verified_at_epoch_millis`
- `updated_at_epoch_millis`

规则：

- `device_local_security_settings` 是被控端本地安全能力和本地允许状态的事实源。
- 服务端策略不能把本地 `allow_* = false` 放宽成 true。
- `allow_privacy_screen` 或 `allow_block_local_input` 从 false 改 true 时必须完成高风险 step-up 并记录 `last_allow_step_up_*`；从 true 改 false 不需要 step-up。
- `last_allow_step_up_challenge_id` 必须引用 purpose 和 `operation_binding_hash` 均匹配本次本地允许项变更的 risk challenge；同一个 challenge 不得跨字段或跨设备复用。
- 平台探测结果只能作为能力参考，最终启用仍以运行时结果为准。

## 8. 审计

必须新增或支持审计动作：

- `privacy_screen_requested`
- `privacy_screen_enabled`
- `privacy_screen_disabled`
- `privacy_screen_failed`
- `local_input_block_requested`
- `local_input_block_enabled`
- `local_input_block_disabled`
- `local_input_block_failed`
- `local_input_restored`

审计 metadata 允许记录：

- `mode`
- `state`
- `platform_status`
- `error_code`
- `session_id`
- `actor_device_id`

禁止记录：

- 屏幕内容。
- 本地按键内容。
- 剪贴板内容。
- 文件内容。

## 9. 客户端 UI

被控端：

- 权限设置页必须有独立开关。
- 本地允许开关从关闭改为允许时，确认界面必须展示 step-up 目的、目标设备、目标能力、发起账号和有效期；用户取消、校验失败或超时不得改变本地允许状态。
- 会话中必须显示隐私屏和本地输入保护状态。
- 失败时必须显示可理解原因。
- 一键断开始终可达。

主控端：

- 会话工具栏可以请求启用或关闭。
- 无权限时按钮不可用并显示原因。
- 启用中、已启用、恢复中、失败状态必须清楚。
- iOS 远控画面中断开入口不得被工具栏或键盘遮挡。

## 10. 测试要求

必须验证：

- 默认关闭。
- 无权限请求被拒绝。
- 被控端本地关闭时，远程或组织策略不能开启。
- 被控端本地 `allow_privacy_screen` 或 `allow_block_local_input` 从 false 改 true 时必须完成 purpose 匹配的 step-up；purpose 不匹配、challenge 过期、已消费或用户取消时，本地允许状态不变。
- 临时协助默认不能启用隐私屏和本地输入锁。
- 启用和关闭都写审计。
- 平台不支持时返回 unsupported。
- 会话断开后显示和输入恢复。
- 远程重启执行前显示和输入恢复。
- 主控端崩溃后被控端恢复。
- 被控端崩溃后重启 watchdog 恢复。
- 网络断开超过重连窗口后恢复。
- 本地安全退出方式可用。
- Windows UAC、锁屏、安全桌面不被绕过。
- Ubuntu Wayland portal 授权取消后不继续锁输入或遮蔽屏幕。
