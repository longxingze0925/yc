# 企业区域路由与数据驻留设计

## 1. 目标

企业私有化和跨区域部署需要明确 Relay 选择、审计日志、对象存储和运维数据的驻留边界。区域路由不能依赖客户端自报，也不能复用 UDP observe 的诊断 `region` 作为权威策略依据。

目标：

- 支持组织级数据驻留策略。
- 支持 Relay 区域 allow/deny 和 fail-closed。
- 明确哪些数据可以跨区，哪些数据不得跨区。
- 私有化部署默认数据留在企业自有环境。
- 区域策略命中、拒绝和降级必须可审计。

## 2. 范围

`V1 Core`：

- 单区域官方托管基础服务。
- `relay_nodes.region` 作为容量和诊断字段。
- 不承诺多区域数据驻留。

`V1 Commercial/M8`：

- 组织级数据驻留策略。
- Relay 区域调度。
- 禁止跨区 Relay。
- 私有化部署区域标识。
- 审计日志和对象存储驻留策略。
- 管理后台配置和审计。

不做：

- 使用客户端自报地区作为权威合规判断。
- 用 UDP observe 诊断 `region` 作为合规策略依据。
- 在禁止跨区时自动转发到其他区域。
- 违反企业驻留策略上传 QA 证据、日志归档或录制文件。

## 3. 数据分类

业务密文：

- 视频帧密文。
- 输入事件密文。
- 剪贴板密文。
- 文件分片密文。

规则：

- Relay 只能转发密文。
- Relay 区域仍受企业策略限制，即使 Relay 看不到明文。

控制和元数据：

- 账号、设备、会话、权限、候选、Relay token、审计、统计。
- 必须按组织数据驻留策略保存。

对象存储：

- 更新包、SBOM、日志归档、QA 证据、未来录制密文。
- 必须绑定 region 和 retention policy。

## 4. 区域策略

组织区域策略字段：

- `home_region`
- `allowed_relay_regions`
- `denied_relay_regions`
- `metadata_residency_region`
- `object_storage_region`
- `audit_log_region`
- `cross_region_fail_policy`

`cross_region_fail_policy` 取值：

- `fail_closed`
- `allow_with_warning`

规则：

- 企业默认使用 `fail_closed`。
- `allow_with_warning` 只允许在明确配置的非严格合规组织中使用。
- 多条策略冲突时，以更严格策略为准。
- 区域不可用且策略为 `fail_closed` 时，必须拒绝 Relay 分配并返回明确错误。

## 5. Relay 调度

Relay 节点必须配置：

- `relay_node_id`
- `region`
- `country`
- `provider`
- `public_endpoint`
- `supports_quic`
- `supports_tls_443`
- `status`
- `max_sessions`
- `active_sessions`

分配规则：

1. 读取会话所属组织或个人默认组织。
2. 读取组织区域策略。
3. 过滤不在 `allowed_relay_regions` 或命中 `denied_relay_regions` 的节点。
4. 按健康、负载、历史质量和网络距离排序。
5. 策略禁止跨区且无可用节点时拒绝分配。
6. 签发 Relay token 时绑定最终 `relay_node_id`。

注意：

- UDP observe 响应中的 `region` 只用于诊断，不参与候选 ID、candidate token 或合规决策。
- 合规区域来源必须来自服务端配置的 Relay 节点、组织策略和部署区域。
- Relay 节点变化必须重新 signed key exchange。

## 6. API 设计

M8 管理 API：

```text
GET  /v1/organizations/{organization_id}/region-policy
PATCH /v1/organizations/{organization_id}/region-policy
GET  /v1/relay-nodes
PATCH /v1/relay-nodes/{relay_node_id}
GET  /v1/regions
```

规则：

- 修改区域策略必须要求管理员权限和 MFA step-up。
- 修改后只影响新会话；已连接会话如违反新策略，必须按策略关闭或等待自然结束，并写审计。
- 私有化部署可以禁用官方 SaaS 区域列表，只使用企业本地 region。

## 7. 数据模型

M8 需要纳入 Schema Freeze 或后续企业迁移的逻辑表：

- `organization_region_policies`
- `region_catalog`
- `object_storage_locations`

`organization_region_policies` 关键字段：

- `region_policy_id`
- `organization_id`
- `policy_version`
- `home_region`
- `allowed_relay_regions`
- `denied_relay_regions`
- `metadata_residency_region`
- `object_storage_region`
- `audit_log_region`
- `cross_region_fail_policy`
- `updated_by_account_id`
- `updated_at_epoch_millis`

规则：

- `region_policy_id` 是策略记录稳定 ID。
- `policy_version` 每次策略变更递增。
- `cross_region_fail_policy` 固定集合为 `fail_closed`、`allow_with_warning`。
- Relay 分配、Relay 统计和区域违规审计必须记录命中的 `region_policy_id` 和 `policy_version`。

`region_catalog` 关键字段：

- `region`
- `country`
- `provider`
- `status`
- `data_residency_class`

`object_storage_locations` 关键字段：

- `storage_location_id`
- `region`
- `purpose`
- `bucket_or_container`
- `retention_policy_id`
- `data_residency_class`
- `status`

规则：

- `region_catalog.status` 在 M8 Schema Freeze 时固定集合为 `active`、`disabled`。
- `object_storage_locations.purpose` 在 M8 Schema Freeze 时固定集合为 `release_artifact`、`sbom`、`audit_archive`、`qa_evidence` 和 `recording_ciphertext_reserved`。
- `object_storage_locations.status` 在 M8 Schema Freeze 时固定集合为 `active`、`disabled`。
- 客户端发布制品、SBOM、日志归档、QA 证据和未来端点侧录制密文必须通过 `storage_location_id` 绑定允许区域。
- `retention_policy_id` 首版只作为外部对象存储或企业留存策略引用，允许为空；如果 M8 要产品化留存策略管理，必须先新增并冻结 `object_retention_policies` 或等价表，再实现策略绑定、审计和迁移。

`relay_nodes` 的区域字段口径固定为：

- `region`
- `country`
- `provider`
- `data_residency_class`

规则：

- `region`、`country` 和 `provider` 是 V1 Core Relay 节点配置字段。
- `data_residency_class` 是 M8/V2 企业区域驻留预留字段；V1 Core 可以为空，不参与 Relay 分配门禁。
- 企业区域驻留提前进入实现时，必须先在 Schema Freeze 中把 `data_residency_class` 升级为明确 CHECK/枚举约束，并同步 Relay 分配、审计和迁移说明。

## 8. 审计

必须新增或支持审计动作：

- `region_policy_created`
- `region_policy_updated`
- `region_policy_evaluated`
- `region_policy_denied`
- `relay_region_selected`
- `relay_region_denied`
- `object_storage_region_selected`
- `data_residency_violation_detected`

审计 metadata 允许记录：

- `organization_id`
- `home_region`
- `selected_relay_region`
- `selected_relay_node_id`
- `storage_location_id`
- `purpose`
- `object_storage_region`
- `retention_policy_id`
- `region_policy_id`
- `policy_version`
- `data_residency_class`
- `cross_region_fail_policy`
- `deny_reason`

禁止记录：

- 业务明文。
- 录制文件明文。
- 剪贴板、文件内容和输入文本。

## 9. 测试要求

M8 必须验证：

- 组织允许区域内 Relay 分配成功。
- 命中 denied region 时拒绝 Relay 分配。
- 区域不可用且 `fail_closed` 时会话不得跨区降级。
- `allow_with_warning` 时必须有用户和审计提示。
- 私有化部署不会连接官方 Relay。
- 审计日志、对象存储和未来录制密文落在配置区域。
- UDP observe 诊断 `region` 不能影响合规决策。
- Relay 节点 region 被篡改或 token 跨节点使用时必须拒绝。
